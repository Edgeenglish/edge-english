D-52 기존 학생 입력 · 확대판 시안 2

지금 화면의 디자인·기능은 그대로 두고 카드 순서와 수강기간 입력 방식만 바꿨어요. 숫자·날짜는 실제 학생 시트 한 장의 구조를 본떠 가상 학생으로 채웠어요(오늘 10/26(월) 기준). 화면 안 버튼은 눌러서 바꿔 볼 수 있어요. 청록 테두리 = 이번에 바뀐 카드.

정책·실제 시트 대조 결과

기준표 POL-PER-01~08, period.ts, 실제 학생 수강현황 시트 1장(PC 탭)의 구조를 읽었어요. 시트·운영 DB는 바꾸지 않았어요.

항목확인한 사실시안 반영
시트에 있는 것학생 시트 맨 위에 '첫번째·두번째·세번째 수강 기간' 시작·종료일, '수강 종료일', '변경권 1회 / 총 2회'가 그대로 적혀 있음대표님은 시트의 수강 시작일만 옮겨 적으면 나머지 기간이 자동으로 나오고, 시트와 한 줄씩 대조
기간 시작일최초 시작일 = 첫 정규 수업일(POL-PER-03), 재등록은 이전 종료 뒤 첫 정규 수업일(A25). 그 뒤 28일씩 이어짐. 확인한 시트도 수요일 수업 학생이 수요일 시작계산은 그대로. 단 수강 중 고정 요일을 바꾼 학생은 기간 시작 요일이 지금 수업 요일과 다를 수 있음 → '경고'가 아니라 '확인' 안내로 바꾸고 막지 않음
연장강사 장기 휴무·학생 장기 연기는 기간 칸은 그대로 두고 마지막 종료일만 늘어남(period.ts). 확인한 시트에도 '강사 장기 휴식 → 수강기간 연장, 보강 TBD' 줄이 있고 종료일은 아직 그대로종료일은 자동 계산값을 넣되 고칠 수 있음. 다르면 며칠 차이 + 이유를 고르게 하고 저장은 막지 않음. 늘어난 날에는 정규 수업을 만들지 않고 보강만 (정규를 더 만들면 남은 수업이 실제보다 많아짐)
옛 상품1판 계약 30일·8주 상품은 다시 계산하지 않고 시트 날짜 그대로(POL-PER-01, CF-04)'시트 기간 날짜가 계산과 달라요'를 누르면 기간 날짜를 한 줄씩 직접 입력
지금 기간오늘 날짜가 어느 기간 안에 있는지로 정해짐'몇 번째 기간' 고르기를 없애고 오늘 날짜로 자동 표시 (입력 1번 줄어듦)

바뀐 점

  1. 카드 순서: 학생 → 수강권 → 강사·정규 수업 → 미완료 보강 → 남은 수업 대조 → 확인·저장
  2. 수강권 카드: 상품 · 수강 시작일 → 기간 전체 목록 자동(지금 기간 강조) · 남은 변경권 · 수강 종료일(자동, 다르면 차이·이유)
  3. 강사·정규 수업 카드: '입력 시작일' 대신 앞으로 남은 첫 정규 수업일(오늘 이후 첫 수업 요일로 자동, 고칠 수 있음)
  4. 미완료 보강: 기본값 '없음' — 없는 학생은 아무것도 누르지 않고 넘어감
  5. 남은 수업 대조: 위 카드를 고치는 즉시 다시 계산
  6. 확인·저장: 만들 수업 날짜·횟수 · 변경권 · 미완료 보강 · 기간 · 종료일을 한 카드에서

'시트와 같음 · 대조 완료', 처리할 일 카드, 충돌 검사, 시트 숫자와 달라도 저장 — 이미 맞게 만든 부분은 그대로예요.

정할 것 (3가지)

① 종료일이 계산과 다를 때 고르는 이유
  1. 강사 장기 휴무 연장
  2. 학생 장기 연기 (24주)
  3. 옛 상품 (30일 기준 등)
  4. 기타 (메모)
이 4개로 충분한지, 더 넣을 이유가 있는지 알려 주세요.
② 30일 기준 등 옛 상품 학생이 지금 있나요?
  1. 있음 → 기간 날짜 직접 입력 버튼을 지금 만들기
  2. 없음 → 버튼은 빼고 나중에 필요할 때
만들고 빼는 데 드는 일이 작아서 어느 쪽이든 괜찮아요. 실제 학생 기준으로 골라 주세요.
③ 이 시안대로 개발해도 될까요? 승인하시면 로컬 → 시험용 DB(필요하면 migration 추가) → 화면 시험 순서로 진행해요. D-52 순서는 그대로예요.

검토 기준 대조

  • ① 취소·변경·보강: 기간·변경권·원래 수업 날짜가 시트와 같게 들어가야 다음 단계 취소·변경 처리가 맞게 동작
  • ② 반복 확인: '몇 번째 기간' 고르기 제거, 기간 목록 자동, 미완료 보강 없으면 건너뜀 → 학생당 입력·확인 동작 감소
  • ③ 불필요 개발: 없음. 새 화면 없이 같은 화면 순서·계산만 바꿈
