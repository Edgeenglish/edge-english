# 대표 요청 원문 (2026-10-18) — LMS를 만드는 가장 중요한 이유

> 다음 세션 작업: 이 목표를 기준으로 **현재 설계에 이미 있는 것 / 빠진 것만 구분**해서 보고. 구현·재설계 아님.
> 이미 확정한 내용(학생 셀프서비스, 정책 자동검증, 스케줄 관리, 관리자 예외 처리)은 유지. 로그인·보안 작업 우선순위는 바꾸지 않음.

Claude, LMS를 구축하는 가장 중요한 이유를 다시 강조하고 싶어.
지금도 학생들이 카카오톡으로 "다음 주 목요일 5시 수업을 7시 이후로 옮길 수 있나요?", "21일 수업을 19일이나 26일로 변경할 수 있나요?" 같은 문의를 보내고 있어.
이런 문의 하나를 처리하려면 내가 학생의 수강기간, 변경권, 취소 규정, 강사의 고정 일정, 다른 학생의 정규 수업과 보강, 시간 충돌, 휴식시간 등을 여러 번 확인해야 해. 학생과 강사에게 각각 확인하고, 일정을 확정하고, 기록을 수정하는 과정까지 전부 수동이야.
이런 업무 때문에 메시지를 확인하는 것 자체가 부담스러울 정도야.
내가 원하는 건 단순히 일정을 보기 좋게 관리하는 LMS가 아니라, 이런 반복 업무를 실제로 없애주는 LMS야.

## 1. 학생이 직접 해결할 수 있어야 해
학생이 본인의 LMS에서 수업 변경·취소·보강을 직접 신청하고, 시스템이 기존 운영정책에 따라 처리해야 해.
- 학생의 수강기간과 남은 변경권 자동 확인
- 수업 시작 6시간 전 규정 자동 적용
- 보강 가능 여부와 기한 자동 판단
- 강사 정규 수업·보강·휴무·다른 예약과 충돌 검사
- 수업 길이 및 최소 10분 휴식 반영
- 일회성 보강으로 해당 요일 전체의 정규 가능 시간이 차단되지 않도록 처리
- 단순 1회 일정 변경과 매주 고정 스케줄 변경은 구분

학생에게는 실제로 신청 가능한 날짜와 시간만 보여주고 싶어.

## 2. 가능한 건 대표 승인 없이 자동 처리
기존 정책과 강사가 사전에 승인한 가능 시간 안에서 해결할 수 있는 정상적인 변경·취소·보강은 대표가 매번 승인하지 않아도 되게 해 줘.
확정되면 학생·강사 일정, 수업기록, 변경권과 보강 상태가 일관되게 갱신되어야 해.
강사에게 추가 확인이 필요한 시간은 자동으로 확정하지 말고, 확인 및 승인 절차를 거쳐야 해.

## 3. 대표에게는 예외만 알려줘
다음과 같은 경우에만 관리자 대시보드의 '처리할 일'에 표시해 줘.
- 학생이 원하는 시간에 배정 가능한 강사가 없는 경우
- 기존 정규 수업이나 보강과 충돌하는 경우
- 강사 휴무로 대체수업 조율이 필요한 경우
- 강사의 별도 승인이 필요한 경우
- 보강 기한이 임박했지만 해결되지 않은 경우
- 자동 처리·알림 발송에 실패한 경우
- 정책상 자동 판단하기 어려운 예외

자동으로 정상 처리된 업무까지 대표에게 계속 알리지 말고, 처리 내역과 감사 기록에서만 확인할 수 있게 해 줘.

## 4. 카카오톡 문의도 고려해 줘
현재 학생 문의는 대부분 카카오톡으로 들어와.
카카오톡을 LMS와 자동 연동하는 것이 이미 구현되어 있다고 가정하지 말고, 학생들이 앞으로 LMS에서 직접 신청하도록 자연스럽게 전환할 방법을 검토해 줘.
필요하다면 학생에게 보낼 LMS 신청 링크나 간단한 안내문을 관리자가 쉽게 복사할 수 있도록 해 줘.

## 5. 기존 개발 내용과 중복하지 마
학생 셀프서비스, 정책 자동검증, 스케줄 관리, 관리자 예외 처리 등 이미 확정한 내용은 유지해 줘.
지금 설계에 이미 포함된 기능과, 아직 빠진 기능만 구분해서 알려줘. 중복 구현이나 불필요한 재설계는 하지 말아 줘.
모바일에서 학생과 강사 모두 쉽게 사용할 수 있어야 하고, 현재 진행 중인 로그인·보안 작업의 우선순위도 변경하지 마.

최종 목표는 명확해.
학생이 스스로 해결할 수 있는 일은 학생과 LMS가 처리하고, 강사가 직접 확인해야 하는 일은 강사가 처리하고, 정말 대표의 판단이 필요한 일만 나에게 넘어오는 구조야.
이 목표를 기준으로 현재 개발 계획에 빠진 부분이 있는지만 확인해 줘.
