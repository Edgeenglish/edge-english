D-52 기존 학생 입력 · 확대판 시안

지금 있는 '기존 학생 간단 입력' 화면(1~3번)은 그대로 두고, 청록색 테두리 칸만 새로 붙여요. 가상 학생 예시이고, 화면 안 버튼·숫자는 눌러서 바꿔 볼 수 있어요. 오늘 날짜 10월 24일 기준.

대표님이 정할 것 (6가지)

① 시트의 '남은 수업 횟수'에 미완료 보강이 들어가 있나요?
  1. 들어가 있음 → 시안처럼 정규 + 보강(예약·미예약)을 합쳐서 시트 숫자와 비교
  2. 따로 셈 → 정규만 시트 숫자와 비교, 보강은 따로 비교
시안은 1번 기준이에요. 시트 실제 모양을 보고 답해 주세요.
② 숫자가 안 맞는 채로 저장하면
  1. 대시보드 '처리할 일'에 "가상기존1 · 남은 수업 1회 차이" 카드를 남김 (정리하면 지움)
  2. 운영 메모에만 적고 끝
Claude 의견: 1번. 메모는 다시 안 보게 돼서 차이가 묻혀요.
③ 모자랄 때 채우는 방법
  1. 두 버튼 다: [+ 추가 수업 날짜](그날 하나만 만드는 수업) · [+ 미예약 보강]
  2. [+ 미예약 보강]만 (날짜는 나중에 보강 잡을 때)
Claude 의견: 1번. 이미 날짜가 정해진 추가 수업이 있으면 그날 강사 시간을 막아야 해요.
④ 보강의 '원래 수업 날짜'
  1. 꼭 넣기 → 원래 날짜가 앞으로의 날이면 그날 정규 수업을 자동으로 안 만듦 (정규·보강 중복 방지)
  2. 선택 (모르면 비워 둠)
Claude 의견: 1번. 미리 취소한 수업이 정규로 또 생기는 걸 막는 유일한 단서예요.
⑤ 저장 뒤 '시트와 대조' 체크
  1. 항목마다 [맞음]을 눌러야 '대조 완료' 기록이 남음 (학생 목록에 대조 완료/전 표시)
  2. 확인 화면만 보여 주고 기록은 안 남김
Claude 의견: 1번. 학생 전원을 넣을 때 누구를 대조했는지 남아요.
⑥ LMS 전환일을 어디서 정할지
  1. 입력 화면은 '아직 시트로 관리'로 고정, 전환일은 나중에 학생 상세에서
  2. 입력 화면에서 바로 날짜를 넣을 수도 있게
Claude 의견: 1번. 취소·보강·Class Record 검증 전에는 전환할 일이 없어서요.

달라지는 것

  • 4. 지금 수강기간: 상품 · 지금 몇 번째 기간 · 그 기간 날짜 · 그 기간 남은 변경권. 다음 기간 변경권은 기존 규칙(주1회 1 · 주2회 2 · 주3회 이상 3)으로 자동
  • 3. 보강: 예약됨 / 미예약 구분 + 원래 수업 날짜
  • 5. 남은 수업 대조: 시트 숫자를 넣으면 만들 수업과 비교. 달라도 저장은 됨. 많으면 뺄 수업을 고르고, 적으면 추가
  • 6. LMS 전환: 입력해도 '시트로 계속 관리' 상태
  • 저장 뒤: 시트와 1회 대조 체크

충돌 검사(다른 학생 수업 · 휴식 10분 · 강사 휴무 · 재등록 대기)는 지금 화면 그대로 써요. 학생·강사에게는 아무것도 보내지 않아요.

검토 기준 대조

① 취소·변경·보강변경권·미완료 보강이 LMS에 들어가야 다음 단계(취소·변경 처리)를 기존 학생에게 바로 쓸 수 있음
② 반복 확인입력 때 1회 대조로 끝. 전환 뒤에는 시트 대조가 사라짐 (전환 전까지는 그대로)
③ 불필요 개발없음. 새 화면이 아니라 기존 입력 화면에 칸 추가

고르시면 만들 때 필요한 것

  • DB: 기간·변경권 저장(기존 표 사용), 미예약 보강 저장 자리(원래 수업이 시트에만 있어 새로 필요), 학생별 전환일·대조 기록 칸
  • 순서: 로컬 → 시험용 DB → 화면 시험 → 대표 승인 → 운영 DB (적용 직전 백업)
