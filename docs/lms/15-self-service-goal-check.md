기준: 대표 요청 원문 [`requests/2026-10-18-self-service-goal.md`](requests/2026-10-18-self-service-goal.md)
범위: **이미 설계에 있음 / 빠짐**만 구분. 구현·재설계 없음. 로그인·보안 작업 순서는 그대로.
대조한 것: 기획서 v2(02), 로드맵(06), 결정(07), 정책 기준표(`policy/register.md`), 규칙 코드(`src/lms/rules/`), DB(`supabase/migrations/`), 대시보드(`src/lms/admin/board.ts`), 대표 Google Docs 정책 원본(A01~A36, H21).

## 2. 정상 건은 대표 승인 없이 자동 처리

| 요청 | 상태 | 근거 |
|---|---|---|
| 확정 시 학생·강사 일정·수업기록·변경권·보강 상태 일관 갱신 | 📐 | 기획 3-5, 한 번에 저장(트랜잭션), `change_requests`(판정 근거·중복 방지 키), `audit_log`, 캘린더 반영(POL-OP-19) |
| **강사가 미리 승인한 시간 안이면 자동 확정** | ⚠️ | 기획 3장·로드맵 4-c: **"모든 보강은 강사 확인 후 확정"** (학생이 후보 2~3개 → 강사 [확정/다른 시간 제안]). 대표 목표와 반대. `tutor_availability`에 '바로 확정 가능 / 확인 필요' 구분 칸 없음 |
| 강사 추가 확인이 필요한 시간은 확인 절차 | 📐 | `makeup_requests`(requested·countered·confirmed), 미확인 시 대표에게 올리는 기한 D-38 |
| **고정 시간 변경 자동 처리** | ⚠️ | 기획 1-1: "고정 요일·시간 변경 승인 = 운영진 직접" |

## 3. 대표에게는 예외만

원칙은 이미 확정(POL-OP-20, 정책 원본 H21). 빠진 것은 **업무 종류**다. 지금 `board.ts`는 7종(신규 매칭, 재등록 강사 통보, 장기 연기, 노쇼 신고, 종료 임박, 보강 미신청, 자동 처리 실패), DB `admin_tasks.kind`는 2종뿐.

| 대표가 받을 예외 | 상태 |
|---|---|
| 원하는 시간에 가능한 강사가 없음 | ❌ 학생이 '원하는 시간이 없어요'를 남기는 경로도, 업무 종류도 없음 (학생이 다른 강사를 직접 고르는 기능은 로드맵상 '지금 불필요' — 유지) |
| 기존 정규·보강과 충돌 | ❌ 업무 종류 없음 (자동 처리 중 충돌로 저장 실패한 경우) |
| 강사 휴무 대체수업 조율 | 📐 기획 8 '강사 휴무 일괄 처리'. 처리할 일 항목은 없음 |
| 강사 별도 승인 필요 / 강사 미응답 | 📐 D-38 기한은 확정, 보강 확인 대기 업무 종류는 없음 (지금은 재등록 통보만) |
| 보강 기한 임박인데 미해결 | ⚠️ 지금 '보강 미신청'은 기한과 무관하게 **전부** 올림 → '기한 임박 + 자동 안내 후에도 미신청'만 올리도록 바꿔야 함 (H21에서 이미 지시, 미반영) |
| 자동 처리·알림 실패 | ✅ 일부 (캘린더·메일 반송·결제 불일치). 자동 확정 저장 실패는 없음 |
| 정책상 자동 판단이 어려운 예외 | ❌ `change.ts`가 판단 불가(status null)를 돌려주는 경우가 있으나 대표에게 넘기는 경로 없음 |
| 자동 처리 건은 '처리 내역'에서만 | 📐 원칙·DB(`audit_log`, `change_requests`) 있음. 관리자 '기록' 화면 없음 |

## 4. 카카오톡 → LMS 전환

| 항목 | 상태 |
|---|---|
| 카카오 자동 연동 없다고 전제 | ✅ A28 반영 (채널 메시지는 대표 수동 발송) |
| 대표가 카톡 문의를 LMS로 대신 처리 | 📐 `change_requests.via = admin_on_behalf`, 로드맵 3단계. **학생이 아직 안 써도, 대표가 같은 '가능한 시간' 화면으로 답하면 수동 확인 작업은 바로 사라짐** |
| 관리자 '안내문 복사' (LMS 링크 + 짧은 안내) | ❌ D-26의 링크 복사는 동의서용만 |
| 카카오톡 채널 채팅방 메뉴·자동 응답에 LMS 링크 고정 | ❌ 검토 없음. 개발 없이 채널 관리 화면 설정으로 가능할 수 있음 — 설정 위치는 실제 화면 확인 후 안내 |

## 5. 모바일·중복 방지

- 학생 메인(A-1) 모바일 시안 확정, 변경·취소 확인창 시안 있음 → 유지.
- **강사 화면은 시안 전**(3단계). 위 2번이 정해지면 강사 화면에 '바로 확정 가능 시간 / 확인 필요 시간' 등록과 [확정·거절]이 들어가야 함 — 강사 화면 시안 전에 정해야 다시 만들지 않음.
- 중복 위험 없음: 빈 시간 계산은 `booking.ts`의 clashes·withinAvailability를 그대로 쓰면 됨. 고정 시간 변경 검사는 `checkRegularPlan` 재사용.

## 대표 결정이 필요한 것 (3개)

| # | 질문 | 추천 | 이유 |
|---|---|---|---|
| D-43 | 강사가 미리 '바로 확정 가능'으로 등록한 시간 안의 보강·1회 옮기기는 **강사 확인 없이 즉시 확정**할까요? 그 밖의 시간은 강사 확인 | **예** | 대표 목표 2번. 지금 기획('모든 보강은 강사 확인')을 바꾸는 것. 강사에게는 "이 시간은 자동 확정됨"을 안내·동의받아야 함 (예: Benny 18시 이후는 '확인 필요'로만 등록) |
| D-44 | 고정 시간 변경도 규칙(28일 1회·4일 전) + 같은 강사 + 바로 확정 가능 시간 + 기간 전체 충돌 없음이면 **대표 승인 없이 자동**? 강사가 바뀌는 변경은 대표 | **예** | 지금 기획은 '운영진 승인'. 규칙 판정은 이미 코드에 있음 |

## 이미 정해진 순서에 끼워 넣을 것 (순서 변경 제안 아님)

1. 위 D-43~45 답 → 기준표·기획서 갱신 (문서만)
2. **빈 시간 계산 규칙** (`booking.ts` 추가, 테스트) — 대표 대리 처리·학생 화면 둘 다 씀
3. 처리할 일 종류 추가 (가능한 강사 없음·충돌·강사 확인 대기·휴무 조율·기한 임박 보강·판단 불가·자동 확정 실패) + '보강 미신청'을 기한 임박만으로
4. 관리자 '안내문 복사'·'처리 내역' 화면 — 대시보드 화면 작업 때 함께
5. 강사 화면 시안에 '바로 확정 가능 / 확인 필요' 시간 등록 포함

로그인·보안(현재 진행)과 D-40~D-42는 그대로 먼저.

### 2차 답변 (2026-10-18)
- **D-44 ✅** 같은 강사가 가능하다고 확인하면 고정 시간 변경 확정(대표 안 거침). 다른 강사를 원하면 운영진 처리. '다음 주부터 적용'은 신청 화면·확정 안내·학생 일정에서 알림.
- **D-46 ◐** 강사 경고: 신청 후 6시간·12시간 두 번, 이메일, 부드러운 문구. 곧 시작하는 시간 신청 처리 방법은 질문 중.
- **D-47 ✅** 학생 보강 미신청 알림: 종료 7일 전 1회 / 7일 안에 생긴 보강은 3일 전 1회 / 3일 안은 취소 확인창 안내로 대신. 확인창 문구에 실제 기한 날짜(예: '11/16까지')를 넣는 것은 화면 작업 때 반영.
- **D-45** 설명 다시 드림.
- **D-46 ✅** 희망 시간 최소 간격 없음. 곧 시작하는 시간을 고르면 학생 안내 필수(문구 초안: "급하게 신청하면 강사님이 제때 확인하지 못할 수 있어요. 확정되기 전까지는 수업이 잡힌 것이 아니에요."). 시작 12시간 안이면 강사 경고는 신청 즉시 1회. 확정 없이 그 시간이 지나면 신청 자동 만료, 보강 권리 유지.
- **D-45** 대표 답 대기 (나중에 답하기로 함).
- **D-45 ✅** 용어 '변경'으로 통일. [변경] → ① 다른 시간으로 변경 신청(가능 시간 먼저 보고 신청, 확정은 강사) ② 지금 빼기만 하고 보강은 나중에. 보강이 없는 경우(6시간 미만·변경권 0개)는 기존 확인창만.
- **D-48 ⬜** 같은 날 10분만 늦추는 것도 변경권 1개인지 (현재 규칙상 예) — 대표 답 대기.
