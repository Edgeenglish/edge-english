# 대표 요청 원문 (2026-10-21) — 신규 학생 강사 매칭 방식 최종 결정 (D-50)

> 다음 세션 작업: 이 요청을 기준으로 **기존 설계·구현에 이미 반영된 것 / 추가로 필요한 것만 구분**해서 간단히 보고. 구현·재설계 아님.
> 이미 확정한 C안 기반 신규 학생 등록 화면(`/lms/admin/students/new`)과 Next.js + Supabase 구조는 유지. 현재 진행 중인 개발 우선순위(D-41 → D-42 …)는 바꾸지 않음.

Claude, 엣지영어 LMS의 신규 학생 강사 매칭 방식을 최종 결정했어.
현재 학생은 약 12명이고, 신규 등록은 일주일에 약 1명 정도야. 따라서 지금은 완전 자동 매칭보다 LMS가 최적의 강사·고정 스케줄 후보를 계산하고, 운영진이 직접 선택하는 방식으로 진행할게.

## 1. 가능한 강사와 스케줄을 최대한 찾아줘
학생이 신청서에 제출한 가능한 모든 요일·시간을 기준으로, LMS가 강사들의 일정과 비교해서 가능한 조합을 계산해 줘.

* 조건에 맞는 강사가 여러 명이라면 3명 등으로 제한하지 말고 모두 보여줘.
* 강사 한 명에게 가능한 고정 스케줄 조합이 여러 개라면 그 조합들도 모두 확인할 수 있게 해 줘.
* 같은 강사가 여러 번 반복되지 않도록 강사별로 묶고, 클릭하면 가능한 스케줄 조합들이 펼쳐지는 방식을 추천해.
* 추천 순위가 낮더라도 실제 가능한 후보라면 숨기지 마.

## 2. 추천 이유를 구체적으로 설명해 줘
단순히 빈 시간 목록만 보여주는 게 아니라, 왜 이 강사와 스케줄을 추천하는지 알려줘.
예를 들어 다음 항목을 고려해 줘.

* 기존 수업과 연속 배치할 수 있어 공백이 적음
* 학생의 학습 목적과 강사의 전문 분야가 잘 맞음
* 향후 다른 학생을 배정하기 좋은 시간대를 보존할 수 있음
* 학생이 희망한 요일과 시간에 잘 맞음
* 강사 일정에 추가 확인이 필요한 부분이 있음

추천 이유는 실제 등록된 정보에 근거해야 해. 학생·강사 적합도를 판단할 자료가 부족하면 임의로 추측하지 말고 '확인 필요'로 표시해 줘.
추천 순서는 LMS가 제시하되, 최종 선택은 운영진이 자유롭게 할 수 있어야 해.

## 3. 일정 계산은 정확해야 해

* 학생의 가능한 모든 시간
* 강사의 기본 근무 가능 시간
* 기존 정규 수업과 보강
* 강사 휴무 및 일시적인 불가능 시간
* 20분·40분·50분 수업 길이
* 수업 사이 최소 10분 휴식
* 주간 수업 횟수 및 첫 수업 시작일
* 전체 등록기간의 일정 충돌

특히 특정 날짜에만 보강이 있다는 이유로 해당 요일의 정규 수업 가능 시간을 영구적으로 제외하지 마. 대신 해당 날짜의 실제 충돌 여부는 별도로 알려줘.
강사는 프리랜서이므로 기본 근무 가능 시간은 참고자료야. 다른 학교 일정이 변경될 수 있어서 강사의 실제 수락 전에는 배정을 확정하면 안 돼.

## 4. 신규 등록 절차

1. 학생 신청서 접수 및 결제 확인
2. LMS가 가능한 강사와 고정 스케줄 조합 계산
3. 운영진이 추천 후보를 비교하고 선택
4. 선택된 강사에게 구체적인 수업 일정 제안
5. 강사가 실제로 수락
6. 학생·강사 양측에 최종 확정 안내
7. 확정 일정 등록 및 첫 수업 준비

강사의 '수업 가능' 답변과 실제 수업 확정은 구분해 줘.
최종 확정 안내가 누락되거나 발송에 실패한 경우에는 운영진에게 경고하고, 완료 처리하지 않도록 해 줘.
현재 WhatsApp이 공식 강사 소통 채널이라는 점도 유지해 줘. 자동 발송 연동이 아직 없다면 자동으로 안내했다고 처리하지 말고 수동 발송·확인 절차를 관리해 줘.

## 5. 앞으로의 확장 방향
현재는 운영진이 강사와 스케줄을 선택하지만, 학생 수가 충분히 늘어나면 LMS가 일반적인 매칭도 자동으로 진행하고 운영진은 예외 상황에만 개입하는 구조로 발전시키고 싶어.
지금부터 향후 자동화가 가능하도록 설계하되, 현재 단계에서 불필요하게 복잡한 AI 매칭 시스템을 만들 필요는 없어. 우선 규칙 기반 추천으로 시작해도 좋아.

## 6. 기존 개발과 연결
이미 확정한 C안 기반 신규 학생 등록 화면과 현재 Next.js + Supabase LMS 구조는 유지해 줘.
기존에 구현하거나 설계한 기능과 중복하지 말고, 부족한 부분만 보완해 줘.
모바일에서도 모든 후보와 추천 이유를 쉽게 확인하고 선택할 수 있어야 해.
우선 기존 설계에 이미 반영된 내용과 추가로 필요한 내용을 구분해서 간단히 보고해 줘. 현재 진행 중인 개발 우선순위를 임의로 변경하지 마.
최종 목표는 스케줄 조합을 사람이 계산하는 업무는 없애되, 학생에게 적합한 강사를 선택하는 판단은 당분간 운영진이 유지하는 것이야.
