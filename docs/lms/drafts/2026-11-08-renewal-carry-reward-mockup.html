재등록 · 보강 이월 · 적립금 — 운영자 화면 시안 5차

학생·금액·날짜는 모두 예시입니다. 버튼·칸은 실제처럼 눌러 볼 수 있고, 저장하기 전 입력은 창을 닫거나 다른 화면에 갔다 와도 남습니다. 코드·DB는 바꾸지 않았습니다.

PC
휴대폰

5차에서 바꾼 것

  1. 입금 시각 칸 없앰 → 입금 날짜만 (필수). 마감이 ‘종료일 오후 11:59 KST’라 입금 날짜가 종료일과 같거나 앞이면 마감 안 (POL-RN-01). 종료일 뒤 날짜면 그 칸 아래 ‘보강 이월 안 됨’
  2. 시작일 직접 수정 검사: 정규 요일이 아닌 날을 고르면 그 칸 바로 아래 ‘○요일이에요 · 정규 요일은 수·금’ + 저장 막힘. [첫 수업일로]로 되돌림
  3. 날짜·요일: 화면의 모든 날짜 요일을 실제 달력으로 계산 (예: 10/7(수)·10/28(수)·11/5(목)·11/18(수))
  4. 입력 보존 세 창 똑같이 (재등록·보강 이월·적립금): ✕·다른 화면 → 입력 남음, 다시 열면 ‘저장하지 않았던 입력을 되살렸어요 [원래대로]’ · [취소] → 입력이 있으면 ‘입력한 내용을 지울까요? [계속 입력] [지우기]’, 없으면 바로 닫힘 · 저장하면 보존 입력 지움
  5. 그대로: PC 2열 · 요일별 시간 · 접힌 수강 상품 · 12시간제 · 간결한 보강 이월 · 적립금 잔액 미리보기 · 대시보드 [재등록 넣기]

개발 메모 (승인 뒤)

  • 입금 날짜만 받으려면 DB 규칙 수정 필요: 지금 결제 기록은 입금 시각이 필수(10/16 설계, 11/8 송O나 재등록도 시각 미확인이라 정오로 기록함). 시각을 비워 둘 수 있게 하고 마감 판정을 입금 날짜로 바꾸는 migration 1건. 기존 기록은 그대로. 신규 등록 화면 결제 칸도 같게 할지 대표 결정
  • 읽기 함수 3개 추가 필요: 이월할 보강 목록 · 운영자용 적립금 내역 · 재등록 일정 겹침 미리 검사(지금 일정 확정과 같은 검사). 모두 읽기만 함
  • 요일별 시간은 지금 정규 일정 표(요일마다 한 줄)와 일정 확정 함수 그대로 씀. 새 표 없음
  • 12시간제 표기 함수는 화면 공용 하나로. 강사 화면 영어는 AM/PM
  • 개발·검증은 시험 DB·lms-test 에서만. 운영 반영은 대표 승인 뒤
