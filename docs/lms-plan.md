## 1. 대표(운영자)가 중요하게 말한 조건·선호 (빠짐없이)

대표 메시지에서 직접 말한 것만 모았다. 이후 모든 작업에 적용된다.

### 1-1. 대표에 대한 사실
- 개발 전문가가 아니다. 개발 용어는 쉽게 설명하고, 대표가 직접 해야 하는 일은 꼭 필요한 경우에만 단계별로 알려 준다.
- 밖에서 휴대폰으로 일하는 경우가 많다 (PC 80 : 휴대폰 20, 외부에서는 휴대폰만). → 관리·운영 기능은 항상 휴대폰에서 쉽게 쓸 수 있어야 한다.
- Google 서비스는 항상 대표 계정 **support@edgeenglish.kr** 을 쓴다. Vercel 권한은 대표에게 있다.

### 1-2. 일하는 방식
- Claude가 할 수 있는 코드 분석·파일 확인·기술 조사·설계·테스트 작성·개발환경 준비·오류 검증은 **스스로** 한다.
- **이미 설명하거나 결정한 것을 반복해서 묻지 않는다.**
- 기술적으로 명확한 부분은 Claude가 가장 적합한 방식을 정해 진행한다.
- 대표 승인이 필요한 것만 묻는다: **운영정책, 요금, 수업 횟수, 개인정보, 외부 서비스 비용** 등. 질문은 모아서 간단히, 가능하면 추천안과 함께. 우선순위대로.
- **확정되지 않은 운영정책을 임의로 확정하거나 코드에 적용하지 않는다.** (미결 규칙은 코드에 기본값으로 넣지 않는다)
- 이미 구축한 시스템은 함부로 다시 만들지 않고 기존 코드를 재사용한다.
- 접근할 수 없는 문서·서비스는 **읽은 척하지 말고 정확히 말한다.**
- 기획서에 적혀 있다는 이유만으로 구현됐다고 가정하지 않는다. 실제 코드·파일 확인 결과로 완료/일부/미구현을 구분한다.
- 기존 문서를 통째로 버리지 않고, **무엇을 왜 바꿨는지 변경 내역을 남긴다.** 기존 내용을 덮어써서 변경 이력을 잃지 않게 한다.
- 문서는 Claude가 나중에 다시 참고할 수 있게 프로젝트 안(`docs/lms/`)에 정리한다.
- 최종 목표: "기존 LMS의 복잡한 구조를 복사하는 것이 아니라, 운영정책이 일관되고 오류가 적으며 **대표 혼자서도 편리하게 운영할 수 있는** 엣지영어 전용 시스템". 최대한 단순하고 안정적이며 유지보수가 쉬울 것.
- 대표는 "중요한 운영정책을 충분히 이해하고 승인한 다음 개발을 진행하고 싶다"고 했다.

### 1-3. 하면 안 되는 것 (승인 없이)
- 실제 운영 중인 **사이트, DB, 시트, 캘린더 데이터 변경** 금지. 기존 파일은 읽기 전용으로 분석.
- **실제 운영 DB 생성·수정, 실제 데이터 이전, 외부 서비스 유료 결제, 공개 배포, 실제 알림 발송**은 반드시 대표 승인.
- 비밀번호·API 키를 코드나 GitHub에 노출 금지.
- 테스트 데이터는 가짜만 (실제 개인정보 사용 금지).
- 보고서·저장소에 **학생·강사 이름이나 개인정보를 복사하지 않는다** (건수만).
- 디자인을 대표가 고르기 전에 실제 서비스에 적용 금지.
- 실제 홈페이지 배포는 테스트 결과를 공유하고 승인받은 뒤.

### 1-4. 화면·디자인
- 운영자·학생·강사 모두 **휴대폰에서 주요 작업을 끝낼 수 있어야** 한다. PC에서도 편해야 한다.
- 휴대폰 화면은 단순 축소가 아니라 **터치 조작에 맞게** 만든다.
- 운영자가 외부에서도 학생 등록, 일정 확인, 취소·보강 처리, 강사 기록 확인을 할 수 있어야 한다.
- 실제 휴대폰·PC 크기에서 테스트한다 (지금까지 390px·1280px 기준).
- 주요 화면은 **서로 다른 시안 3개**를 먼저 보여 준다. 색만 다른 것이 아니라 **레이아웃·동선이 달라야** 한다. PC·휴대폰 모습을 모두, 장단점과 추천안 포함.
- 기존 엣지영어 홈페이지와 통일감 (보라 #7d5fff 계열·노랑 #ffd401·남색 #09246b).

### 1-5. 운영정책 관리 (대표가 "가장 우려하는 것")
- 계약서·FAQ·학생 안내문·강사 안내문·시트·홈페이지·기획서에 같은 정책이 다르게 적혀 있을 수 있고, 누적되면 수업 횟수·환불·보강·강사 급여에 심각한 문제가 생긴다.
- **여러 문서가 충돌한다고 최신 문서나 계약서 문구를 무조건 고르지 않는다.** 계약의 법적 효력, 실제 적용 방식, 학생에게 안내한 내용, 정책 변경일을 구분한다.
- **기존 학생·강사와 신규 학생에게 다른 조건이 적용될 수 있다.** 확인되지 않은 것은 하나로 통일하지 말고 대표 결정을 받는다.
- 충돌은 수업 횟수·금전·계약 관련부터 처리.
- 처음부터 복잡한 정책관리 시스템을 만들지 않는다. **관리하기 쉬운 기준 문서 + 충돌 점검 체크리스트**로 시작하고, 나중에 자동화할 가치가 있는지 판단.
- 운영규칙을 단순화한다는 이유로 확정된 학생 권리나 강사 계약 조건을 임의로 바꾸지 않는다.
- 대표가 가장 우려하는 것(2026-10-16 오후): **기존 학생·강사마다 서로 다른 계약 조건이 적용될 가능성.**
- 계약서 날짜만으로 판단하지 말고 실제 서명·갱신·변경 동의 여부를 구분한다.

### 1-6. 계약서·안내서·동의 (2026-10-16 밤)
- **계약서를 받지 않은 학생에게 존재하지 않는 계약서 판본을 임의로 적용하지 않는다.**
- 모든 학생에게 같은 시점에 안내서를 전달했다고 가정하지 않는다.
- 법적 판단이 필요한 부분은 '미확인'으로 표시한다.
- 기존 학생에게 새 안내서를 보여 준다는 이유만으로 과거 계약 조건을 자동으로 바꾸지 않는다.
- 재동의 시점, 재등록 시 별도 동의 필요 여부, 미동의 학생의 수업 처리는 **법적·운영상 검토 후 대표가 결정**.
- **동의하지 않았다는 이유로 실제 학생의 수업이나 등록을 임의로 차단하지 않는다.**
- 개인정보 처리 동의·마케팅 동의를 수강규정 동의 하나로 뭉뚱그리지 않는다.
- 수강규정 클릭 동의만으로 모든 법적 요건을 충족한다고 가정하지 않는다.
- 동일한 학생·등록·계약 판본 데이터를 재사용하고 중복 관리하지 않는다. 동의 내역을 정책 관리 체계와 연결한다.
- 기능의 목적: 대표가 학생마다 계약서·안내 이미지를 일일이 보내고 확인하는 업무를 줄이면서, 학생별로 어떤 조건을 안내하고 동의받았는지를 정확하게 관리.
- 기존 문서·코드 분석, 설계, 안전한 테스트는 자율 진행. **실제 기능 구현 범위와 디자인은 대표가 확인한 뒤 결정.**

### 1-7. 프로젝트 범위 (대표가 "잊지 말라"고 한 것)
- LMS는 **Next.js + Supabase** 기반. 실제 코딩·기술 구현은 Claude, 운영정책 결정·최종 승인은 대표.
- **수강 후기 홈페이지 노출·관리자 웹앱은 이미 완료** → 중복 개발 금지. LMS와 통합할 필요가 있는지만 검토.
- 강사 장기 휴무와 여러 수업 일괄 처리 기능 고려 (예: 2026-11-02~11-10 한 강사 장기 휴무).
- **환불정책은 개편 보류.** 수수료만 공제하는 방안을 고려 중이지만 법적 적합성 미확인 → 자동 계산 금지, 운영자 수동 처리·승인 기능만.
- 강사 급여·인센티브는 문서끼리 수치가 다를 수 있으므로 **최종 기준 확인 전에는 자동 정산에 적용하지 않는다.** 정산 금액은 운영자가 최종 확인·승인.
- 홈페이지 개선(인스타그램 릴스 → 상담·등록 연결, 메인 '실제 수업 모습' 섹션)은 **LMS와 섞지 않고 별도 과제**로 관리 → `docs/homepage/backlog.md`.

### 1-8. 대표가 ChatGPT와 정리했다고 알려 준 운영사항 (첫 메시지)
- 기존 구조: Master Sheet → 학생별 수강현황 → 강사별 Class Record.
- Student ID 영구 고유번호. 신규 학생은 운영자가 **한 번만 등록**하면 학생 화면·강사 화면·수업 일정이 자동 연결.
- 재등록 시 학생을 새로 만들지 않고 Student ID 유지. 재등록 시 기존 고정 스케줄 유지가 기본.
- 수강등록 이력, 수업 이력, 변경 이력, 이월 수업을 구분.
- 운영 DB가 하나의 데이터 원본, Google Sheets는 이관·검증·보고용.
- 학생마다 구글시트 파일을 만들기보다 **본인 정보를 보여 주는 웹앱 화면**을 우선 검토.
- 수강기간 4주·12주·24주. 최초 시작일 = 첫 정규 수업일. 4주 = 28일(시작일 포함). 12주 = 28일 × 3, 24주 = 28일 × 6. 주말·공휴일 시작도 같은 계산.
- 수업은 매주 고정 요일·고정 시간이 원칙. 보강만 가능한 시간을 골라서 잡음(정규 수업을 매번 예약하는 시스템 아님).
- 수업 시작 6시간 전까지 정상 변경. 6시간 미만 취소는 보강 없이 1회 소진·변경권 유지(기획서 방향).
- 학생이 본인의 변경권·보강 가능 여부를 직접 확인할 수 있어야 함.
- 강사 사유 취소는 학생 변경권을 차감하지 않음. 강사 노쇼는 운영자가 확인·확정.
- 보강은 담당 강사가 가능한 시간을 확인한 뒤 확정. 보강 신청·확정은 중복 예약 방지 필수.
- 변경권 소진, 공휴일 예외, 확정된 보강 재취소 등은 세부 규칙 검증 필요. Class Status 14개와 Master 상태매핑표 일치 확인.
- 강사마다 Class Record 사용. 모든 예정 수업은 실제 진행 여부와 관계없이 기록. 강사는 수업 후 **10분 이내 기록**, 기록 시간은 인센티브에 사용. 기존 기록 항목·상태값 최대 유지.
- 강사 사유 취소·대체강사·학생 노쇼 등에 따른 급여 지급 여부를 명확히 구분.
- 학생들은 기존처럼 카카오톡으로 후기를 보내고 대표가 익명으로 등록.
- 시간: UTC 저장 + 현지 시간 변환을 검토하되, **운영정책과 기간 계산은 한국 시간 기준**.
- 강사 1명당 학생 10명 이하(프리랜서, 규모 작음) — 이전 Claude 대화에서 대표가 말한 사실.

### 4-2. 기존 시트 구조의 문제 (01·08 문서)
- Master Sheet에는 시험용 학생 3명만. 실제 운영은 강사별 Class Record + 학생별 시트 중심(대부분 수동).
- Master는 1·2·3차 기간 칸만 있어 **24주(6기간) 미지원**, 재등록마다 칸을 덮어써 이력 보존 불가, 표시용 이름에 시각이 소수(0.708333)로 섞임.
- Class Record가 두 형식(이름 연결 vs Student ID 연결), 고정 시차(+2)로 서머타임 때 틀어짐, **기록 시각 칸 없음**(10분 기준 측정 불가), 'free trial' 옛 값.

- `generateStudentSheet`는 학생 시트 파일을 만들지 않고 이미 있는 파일에 채우기만 함.

- 동의 시안 안의 문구는 예시 초안이고, 미결 항목은 '결정 후 문구'로 비워 둠.

### 5-7. 보류 (자동화하지 않음)
- 환불 자동 계산, 적립금, 수강권 양도, 자체 카드 결제(PG), 카카오 로그인·알림톡·왓츠앱, 학생이 다른 강사 보강을 직접 고르기, 챗봇, 공지·이벤트·강사진 관리 화면, 학습 리포트·숙제, 운영 통계, 후기 시스템 통합.

### 5-8. 법률 검토가 필요한 것 (모두 미확인, Claude가 판단하지 않음)
1. 예전 계약(9조 유무별)이 안내서만 받은 재등록분에도 이어지는지
2. 결제 후 받은 안내서·온라인 동의가 그 등록의 조건이 되는지
3. 클릭 동의의 증명력과 필요한 기록 범위(IP·기기 정보)
4. 약관 명시·중요 내용 설명 의무 (환불·장기 연기 등)
5. 온라인 판매의 거래조건 고지·청약철회와 현재 FAQ 환불 기준(학원법 인용)의 관계, 엣지영어에 어떤 법이 적용되는지
6. 개인정보: 수집 항목 고지, 해외 강사에게 학생 정보 제공(국외 이전), 보관 기간, 미성년 학생 여부
7. 기존 학생에게 불리한 조건(예: SC1 4·6·10회 → 1·2·3회)을 새 판 동의로 바꿀 수 있는지
8. 환불 '수수료만 공제' 방식의 적법성

### 5-9. 번호 관련 메모
- 결정 번호에 **D-20이 없다.** 처음부터 비워 둔 것인지, 만들었다가 지운 것인지 **불확실**. 새 결정을 만들 때 D-20을 재사용하지 말고 D-27부터 쓰는 것을 권한다.

## 8. 불확실한 것 모음

- 대표가 개발 순서 조정안(2-4)에 동의했는지 — 명시적 답 없음.
- '변경은 즉시 처리, 보강 신청은 분리' 제안(2-3 ⑤) — 대표 응답 없음.
- D-20 번호가 비어 있는 이유.
- 계약서 발송 중단 정확한 날짜, 계약서를 보내던 시기의 발송 시점(결제 전/후)·재등록 때 재발송 여부.

- 현재 수강 중인 학생 중 SC1 등 옛 계약 판본 학생이 있는지·몇 명인지 (Drive 파일은 13명분, 본문을 모두 확인한 것은 아님).
- 강사별 실제 지급 시급 기준(17·15·11), 서명본을 못 찾은 강사 3명의 계약 판본.
- 강사 가이드의 '학생 쿠폰'을 실제로 줘 왔는지.
- Vercel 현재 요금제.
- Master 중계 웹앱 전체 코드와, 학생이 A1을 바꿔 다른 학생을 취소할 수 있는지(Master 쪽 검증 여부).
- 시트에 묶인 Apps Script·트리거 전체, Google 캘린더 실제 연동 방식.
- 요금·한도 정보(Supabase·Vercel·Resend·알림톡)는 2026-10-16 검색 기준 추정이며 결제 전 재확인 필요.
