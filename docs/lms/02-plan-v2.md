## 1. 개요

목표(유지): 운영진이 일상 업무에 개입하지 않아도 엣지영어 방식대로 굴러가는 화상영어 시스템. 가장 급한 것은 학생·강사가 운영진을 거치지 않고 수업 변경·보강을 처리하는 것.

서비스(유지): 한국 성인 학습자 ↔ 미국·캐나다·호주 원어민 강사 1:1. 수업 20·40·50분, 주 1·2·3·5회, 수강 4·12·24주.

**[변경] 기술 구조**: 웹앱(Next.js, 기존 홈페이지 프로젝트) + **Supabase(PostgreSQL)가 유일한 데이터 원본**. Google 시트는 이관·검증·보고용, Google 캘린더는 DB에서 만든 복사본. → [05-architecture.md](05-architecture.md)

현재 도구 (2026-10-16 확인 → [01-current-state.md](01-current-state.md))

| 영역 | 지금 | LMS 이후 |
|---|---|---|
| 홈페이지 | Next.js (GitHub → Vercel) | 그대로 + 학생·강사·운영자 화면 추가 |
| 학생·강사 데이터 | Master Sheet + 강사별 Class Record + 학생별 수강현황 시트 | DB. 학생별 시트 파일 대신 **학생 화면** |
| 수업 일정 | 엣지영어 계정 소유 강사별 보조 캘린더 | DB가 원본, 캘린더는 자동 반영 |
| 수강 신청 | 구글폼 | 유지 (운영자가 응답을 보고 등록 화면에서 한 번 등록) |
| 결제 | 계좌이체 + 아임웹 카드 링크 | 유지 |
| 학생 소통 | 카카오톡 채널 | 유지 + 이메일 알림 |
| **[변경] 수강후기** | ✅ 완성 (운영자 관리 화면 → 홈페이지 자동 반영) | 그대로. LMS와 통합하지 않음 |

### 1-1. 자동화 범위 (유지)

| 구분 | 내용 |
|---|---|
| 자동 | 수업 변경·보강 신청과 규칙 검사, 강사 확정 알림, 캘린더 반영, 상태값 기록, 변경권 계산, 재등록 안내, 서머타임 안내, 수업 기록 독촉 |
| 운영진 직접 | 입금 확인, 강사 배정, 고정 요일·시간·담당 강사 변경 승인, 강사 노쇼 확정, 환불 승인, 예외·분쟁 처리, **[추가] 강사 휴무 일괄 처리 방식 선택, 정산 최종 승인** |
| 운영진 사본만 | 학생 변경·보강 신청, 강사 확정 (강사 무응답 때만 알림) |

**[변경]** 도입은 작게 시작(강사 1~2명 시범) + 문제가 생기면 시트로 되돌아갈 수 있게 DB → 보고용 시트 내보내기 유지.

## 2. 사용자와 권한 (유지 + 보완)

| 역할 | 볼 수 있는 것 | 할 수 있는 것 | 언어 |
|---|---|---|---|
| 학생 | 내 일정, 남은 회차, 남은 변경권, 담당 강사, 강의실 링크 | 수업 변경, 보강 시간 선택, 장기 연기 신청 | 한국어 |
| 강사 | 내 수업 일정, 담당 학생의 수업용 정보(표시 이름·국가·성별/나이대·영문 자기소개·레벨·교정 선호·이메일), 내 정산(승인된 것) | 수업 기록, 강사 사유 취소, 수업 가능 시간 설정, 보강 확정 | 영어 |
| 운영진 | 전체 | 학생 등록·배정, 입금 확인, 예외 처리, 규칙값 수정 | 한국어 |

- 로그인이 곧 본인 확인. Student ID 입력 없음. **[추가]** 회원가입 없음 — 운영자가 등록한 이메일만 로그인. 방식은 [미결 D-5] (추천: 학생·강사 이메일 6자리 코드, 운영자 Google).
- 강사는 다른 강사의 학생·일정을 볼 수 없음. **[추가]** 강사에게 학생 휴대폰·한글 실명·운영 메모는 보이지 않음.
- **[변경] 시간 저장**: 기존 "모든 시간은 KST로 저장" → **실제 시점은 UTC로 저장하고, 고정 수업 시각·운영 규칙·기간은 KST로 계산**, 화면은 각자의 IANA 시간대로 표시. (KST는 서머타임이 없어 결과는 같지만, 해외 시간대 변환·캘린더 연동이 정확해짐)

## 3. 핵심 기능: 수업 변경·보강 셀프서비스

흐름(유지): 학생이 변경할 수업 선택 → 규칙 검사 → 보강 희망 시간 2~3개 신청 → **모든 보강은 강사 확인 후 확정** → 캘린더·기록·알림 자동.
용어(유지): 학생 화면에서는 '취소' 대신 '변경'. 옮기기·빼기 모두 변경권 1개.

### 3-1. 학생 흐름

1~4 유지.
5. **[변경 제안]** 기존: "신청 중에는 변경권을 임시로 잡아두고 확정되면 차감". → **변경(빼기)은 누르는 즉시 처리(변경권 사용, 보강 받을 권리 생김), 보강 신청은 그다음 단계로 분리.** 강사가 거절해도 학생은 다른 시간을 다시 고르면 되고, 변경권을 '잡아 두는' 중간 상태가 없어져 오류가 줄어듦. (반대하시면 원안대로)

### 3-2. 강사 흐름 (유지)
주간 가능 시간 등록, [이 시간 확정]/[다른 시간 제안], 무응답 재알림 기준 [미결 D-11], 개인 일정은 '바쁨'으로만 읽음, 강사 사유 취소는 변경권 차감 없이 보강 안내.

### 3-3. 규칙 (검사 순서)

1. 수강 기간 안인지 → 2. 시작 전인지 → 3. 6시간 전까지면 정상 변경(변경권 사용) → 4. 6시간 미만은 늦은 변경(보강 없음, 1회 소진, 변경권 유지, 확인 팝업) → 5. 변경권 0개면 보강 없이 1회 소진.

**[변경]** 기존 2번 "보강 수업도 정규와 똑같이 취소·변경" 은 FAQ("재보강 불가")와 모순 → [미결 D-2].

| 항목 | 규칙 | 상태 |
|---|---|---|
| 수강 단위 | 4주 / 12주 / 24주 ("1개월 = 4주 기준" 표기) | 확정 |
| 기간 계산 | 시작일 = 첫 정규 수업일, 종료일 = 시작일 + 27일, 12주 = 3기간, 24주 = 6기간 (주말·공휴일 시작도 동일) | 확정 (테스트 완료) |
| 변경권 | 28일 기간마다 주1회=1, 주2회=2, 주3회 이상=3. 기간이 바뀌면 새로 지급(이월 없음) | 확정 |
| 6시간 기준 | KST 수업 시작 시각 기준, 6시간 정각까지 정상 | 확정 |
| 임박 변경 | 버튼 하나, 누른 시점에 남은 시간 계산해 맞는 팝업 | 확정 |
| 보강 기한 | 최종 종료일(KST) 23:59까지 시작하는 수업 | 확정 |
| 보강 못 잡은 수업 | 기본 소멸, 재등록 시 이월 — **이월 기한 [미결 D-1]** | 미결 |
| 장기 연기 | **[미결 D-3]** (FAQ·계약서·PDF가 모두 다름) | 미결 |
| 변경권 0개 | 사전 변경해도 보강 불가, 1회 소진 | 확정 |
| 공휴일 | 수업 정상 진행, 6시간 전 변경 시 변경권 차감 없음(0개여도 가능), 보강 가능 — **어떤 날이 공휴일인지 [미결 D-4]** | 규칙 확정 / 범위 미결 |
| **[추가] 고정 시간 변경** | 4주에 1회, 적용 첫 수업 4일 전까지 요청, 다음 주부터 적용, 운영자 승인 (수강계약서·FAQ 기준) | 문서 일치 |

### 3-4. 빈 시간 계산 (유지)
보강 후보 = 강사 가능 시간 − 잡힌 수업 − 재등록 대기 − 막은 날. 30분 단위, 원래 수업 길이. **[변경]** 겹침 방지는 화면 계산뿐 아니라 DB 제약으로 보장 (동시에 확정해도 하나만 성공).

### 3-5. 확정 후 자동 처리 (유지 + 보완)
캘린더 반영, 상태·보강 연결 기록, 학생 한국어·강사 영어 알림·운영진 사본, 모든 변경 이력·복구. **[추가]** 캘린더 반영이 실패해도 수업 변경은 유지되고 재시도·관리자 표시.

### 3-6. 수업 당일: 지각과 노쇼 (유지)
학생 노쇼 1회 소진 / 강사 지각은 강사가 'Tutor Late - Student Present' 선택 / 강사 노쇼: 5분 뒤 학생 신고 버튼, 운영진 확정 [미결 D-9] / 보상: 보강 1회 + 보상 1회, **사용 기한 [미결 D-8]**. **[추가]** 보상 수업은 강사 급여·인센티브 없음 (강사계약서 6-5).

### 3-7. 수업 상태값 14개 (유지, 검증 완료)
Master Sheet 상태매핑표와 PDF 표가 14개 모두 일치 (자동 테스트). 학생에게는 학생용 문구만 표시. **[추가]** D-2 결정에 따라 '보강 재취소' 상태 1개 추가 가능.

## 4. 학생 대시보드 (유지 + 변경)
모바일 우선. 수강 요약, 변경권, 수업 목록 + [수업 변경], 강의실 링크·수업 노트, [강사가 안 들어왔어요], 장기 연기 신청(대상자만), 고정 시간·강사 변경 요청, 알림 설정, 재등록 안내, 변경 이력.
**[변경]** 학생별 구글시트 파일을 새로 만들지 않고 이 화면으로 대체 (링크 유출 위험 제거). 처음에는 보기 전용으로 켬.

## 5. 강사 대시보드 (유지 + 변경)
My Schedule(현지+KST), Class Record 입력, My Students, Availability, My Pay, 기록 독촉, 노쇼 신고 알림. Class Status 14개 그대로.
**[변경]** 기록 시각은 서버가 자동 저장 (현재 시트에는 기록 시각 칸이 없어 '10분 안 기록'을 측정할 수 없음). 시스템이 이미 아는 취소(학생 변경·강사 취소)는 자동 기록되어 강사는 실제 진행 대상 수업만 기록.

## 6. 수강 신청·결제·등록 확정

**[변경]** 순서 유지: 결제 → 구글폼 신청서(입금자명) → 카카오톡. 이에 맞춰:
- 신청 상태는 **'입금 확인 대기'** 로 시작 (기존 '입금 대기' 아님).
- **24시간 자동 재안내 메일 삭제** (이미 입금한 학생에게 잘못 갈 수 있음). 운영자가 [입금 미확인 안내] 버튼을 누를 때만 발송.
- 결제할 금액은 신청 내용으로 계산해 운영자 확인용으로 표시, 실제 입금액과 다르면 경고.
- 운영자가 입금 확인 → 강사·고정 시간 배정 → **등록 화면에서 한 번 저장하면** Student ID·수강등록·기간·변경권·정규 회차·학생 계정·강사 화면 연결이 모두 생성. (배정 전에는 수업 시간 확정 안내를 보내지 않는 원칙 유지)

## 7. 재등록과 일정 충돌 방지 (유지 + 미결)
- 재등록 시 **기존 Student ID·담당 강사·고정 요일·시간 유지가 기본**, 새 수강등록 행으로 이력 보존. 새 시작일 = 이전 최종 종료일 다음 날.
- 재등록 대기(시간 맡아 두기) 기간과 이월 기한 → **[미결 D-1]** (추천: 둘 다 종료 후 7일로 통일).
- 재등록 안내 시점(마지막 2회 전, 종료 3일 전, 종료 당일)은 관리자 화면에서 변경 가능 (유지).

## 8. 운영진 관리자 화면과 강사 정산

관리자 화면 (유지 + 추가): 오늘 현황, 학생 목록, 입금 확인, 강사 배정, 요청 접수, 변경 이력·복구·대리 처리, 강사 관리, 규칙값 수정, **[추가] 강사 휴무 일괄 처리**(강사·기간 선택 → 영향 수업 미리보기 → 학생별 대체 강사/기간 연장/보강 선택 → 한 번에 반영·되돌리기), **[추가] 캘린더·알림 실패 목록**, **[추가] 공휴일 관리**. **[삭제] 후기 게시 승인** (기존 후기 시스템에서 처리 중).

강사 정산 (월별): 지급 대상은 상태매핑표 기준. 수치는 PDF·급여정책(2026-03-27)·강사계약서(2026-08-24)가 일치($11 기본, +$1.50/+$2/+$2/+$0.50, 최대 $17, 30분 단위 내림)하지만 옛 자료와 다르고 세부 공제 규칙이 남아 있어 **[미결 D-13~15]**. **[변경]** 자동 계산은 미리보기, 최종 금액은 운영자 승인 후 강사에게 공개.
