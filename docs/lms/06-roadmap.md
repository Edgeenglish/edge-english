# 06. 개발 순서와 단계별 완료 조건

## 제안하신 순서에 대한 검토

제안하신 순서(분석 → 신규 학생 자동 등록 → 휴무·예외 → 학생 변경·보강 → 캘린더·알림·재등록 → 기록·정산)는 **큰 방향이 맞다.** 모든 기능이 '수강등록과 수업 회차'가 있어야 돌아가므로 등록이 먼저인 것이 개발 의존성상 정답이다. 기존 PDF의 '학생 셀프서비스 먼저'보다 운영 위험도 낮다.

다만 운영 위험 기준으로 세 가지를 바꾸는 것을 추천한다.

| 바꿀 점 | 이유 |
|---|---|
| ① **기존 학생 이관 시험을 2단계에 포함** | 신규 학생만 DB에 넣으면 시트와 DB 두 곳에서 학생을 관리하게 됨. 이관은 '여러 명 한꺼번에 등록'이라 등록 기능과 같은 코드를 씀 |
| ② **강사 수업 기록(Class Record 입력)을 6단계에서 3단계로 당김** | DB가 원본이 되는 순간 수업 결과도 DB에 기록돼야 남은 회차·변경권이 맞음. 강사가 시트에만 적으면 DB 숫자가 틀어짐. 정산 계산만 6단계에 남김 |
| ③ **학생 화면은 '보기 전용'을 먼저** | PDF 11-2 원칙과 같음. 남은 회차·변경권이 시트와 같게 나오는지 확인한 뒤에 셀프 변경을 켬 |

## 단계별 계획

### 0단계 — 기획 정리 (이번 작업, 완료)
- 기획서 검토·수정, DB 설계 초안, 규칙 자동 테스트 39개, DB 검증 32개, 결정 필요 사항 정리.

### 1단계 — 기반 준비
- 할 일: Supabase **시험용** 프로젝트(무료), 스키마 적용, 로그인(이메일 코드·운영자 Google), 가짜 데이터, 별도 브랜치·미리보기 주소.
- 운영자 할 일: Supabase 가입(support@edgeenglish.kr, 무료) — 그때 단계별 안내.
- 완료 조건: 미리보기 주소에서 가짜 학생·강사·운영자 계정으로 각각 로그인되고, 서로의 정보가 안 보임(권한 테스트 자동 통과).

### 2단계 — 운영자: 학생 한 번 등록 → 수업 자동 생성
- 신규 학생 등록 화면: 학생 정보 + 수강(4·12·24주, 횟수, 길이) + 담당 강사 + 고정 요일·시각 + 첫 수업일 → 저장 한 번으로 Student ID, 수강등록, 28일 기간, 변경권, 정규 회차 전부 생성. 강사 시간 겹침은 저장 전에 알려 줌.
- 재등록: 같은 Student ID, 기존 강사·요일·시각이 채워진 상태에서 기간만 고름. 이월 회차 입력(규칙 확정 전에는 운영자 수동).
- 입금 확인: 결제할 금액(수업료 페이지와 같은 가격표) vs 실제 입금액, 다르면 경고.
- 학생 목록·상세(일정·남은 회차·변경권·이력), 오늘 수업.
- 기존 학생 이관 → **시험 DB에만** 넣고 시트와 비교표 생성.
- 완료 조건: ① 가짜 학생 20명 등록 시 회차·종료일이 규칙 테스트와 100% 일치, ② 이관 비교표에서 현재 학생 전원의 남은 회차·종료일이 시트와 일치(다른 것은 원인 확인), ③ 휴대폰(390px)·PC(1280px)에서 등록 1명을 3분 안에 완료.

### 3단계 — 강사 기록 + 운영자 예외 처리 (→ 시범 운영 시작 가능)
- 강사 화면(영어): 내 일정(현지·KST 시각), 수업 기록 입력(Covered Topics·상태·Remarks, 기록 시각 자동), 내 학생 정보.
- 운영자: 카톡으로 받은 요청 대신 처리(취소·변경·보강 입력), 강사 사유 취소, **강사 휴무 일괄 처리**(미리보기 → 학생별 대체/연장/보강 선택 → 한 번에 반영 → 한 번에 되돌리기), 노쇼 확정, 변경권 수동 복구.
- 시범 운영: 강사 1~2명과 그 학생만 DB로 운영, 나머지는 시트. DB → 보고용 시트 매일 내보내기.
- 완료 조건: ① 같은 시간 동시 확정·두 번 누르기 시험에서 중복 0건, ② 휴무 일괄 처리 후 되돌리기 시 원래 상태와 완전히 같음, ③ 시범 2주 동안 남은 회차·변경권이 운영자 수기 확인과 일치.

### 4단계 — 학생 셀프서비스
- 4-a 보기 전용: 내 일정, 남은 회차·변경권, 강의실 링크, 변경 이력.
- 4-b 셀프 변경: [수업 변경] 버튼 하나 → 규칙 검사 → 상황별 팝업(6시간 미만, 변경권 0개, 공휴일).
- 4-c 보강 신청: 강사 가능 시간 중 2~3개 선택 → 강사 [확정 / 다른 시간 제안] → 확정 즉시 반영.
- 완료 조건: 휴대폰에서 1분 안에 변경·보강 신청, 규칙 테스트의 모든 경우가 화면에서도 같은 결과, 시험 학생·강사 계정으로 예외 상황 점검표 통과.

### 5단계 — 자동화
- 이메일 알림(변경·확정·기록 독촉·무응답 재알림), 재등록 안내·재등록 대기 시간 막기, 서머타임 안내, Google 캘린더 반영(비교만 → 실제 반영 순서).
- 완료 조건: 같은 알림 중복 0건, 캘린더 대조에서 DB와 차이 0건이 1주 유지, 실패 시 관리자 화면 표시 확인. **실제 발송·캘린더 쓰기는 운영자 승인 후 켬.**

### 6단계 — 기록 자동 검사·정산
- 미기록·10분 초과 기록 자동 표시, 월별 정산 미리보기(승인된 급여 기준으로만), 운영자 최종 승인, 강사는 승인된 금액만 봄.
- 완료 조건: 지난달 실제 정산(시트) 결과와 미리보기가 일치하거나 차이 원인이 설명됨. 급여 기준 확정 전에는 시작하지 않음.

## 작업 방식
- 모든 개발은 별도 브랜치 → Vercel 미리보기 주소에서 확인 → 승인 후 합침.
- 화면은 시안 3개를 먼저 보여 드리고 고르신 것만 만듦.
- 운영 DB 생성·데이터 이관·유료 결제·실제 발송·공개 배포는 매번 승인 후.
