# 19. 반복 업무를 가장 빨리 없애는 개발 순서 — 제안 (2026-10-23 — 5절에 대표 확정)

근거: 대표 실수·업무 보고(2026-10-23, 아래 1절), 정책 원본 H22~H25 (원본 문서 H22 이후 끝까지 읽음), 현재 DB·코드.

## 1. 대표 보고 요약
- 실수: ① 신규 확정 안내를 학생에게만 보냄 ② 취소할 수업 날짜를 잘못 고르고, 보강 날짜만 안내함(원래 날짜는 안 적음) ③ 이미 취소된 수업에 대해 강사가 학생에게 이메일을 보냄 — 셋 다 **한쪽에만 안내 / 날짜를 사람이 옮겨 적음**
- 대조 업무: 수업 날짜·상태 ↔ 차감 회차 ↔ 보강(잡았는지·끝났는지·빠진 것) ↔ 변경권(남은 수·차감·복구) ↔ Class Record·정산(강사별 학생 필터, Class Count·시간, 운영 실수로 못 했지만 지급할 수업) + 종료일·재등록
- 목표: 수업 상태를 한 번 기록하면 학생 수강현황·Class Record·변경권·보강·정산이 모두 따라옴. 학생 12→30→50명에도 반복 업무가 늘지 않음 (H25)

## 2. 이미 있는 것 / 없는 것
| | 상태 |
|---|---|
| 한 곳 기록 구조 | ✅ 설계·DB 있음: 수업 1건(`lessons`)에 결과(`class_status`) 하나 → 회차 차감·변경권·강사 지급이 상태표(14개)에서 자동 계산. 보강은 원래 수업과 연결(`makeup_of`), 같은 수업 보강 중복·변경권 이중 차감·시간 겹침은 DB가 막음 |
| 신규 확정 양쪽 안내 (실수 ①) | ✅ 만들어짐 (A39, [보냈어요] 둘 다여야 완료). 운영 DB 화면만 열면 사용 가능 |
| 실제 취소·변경 처리 (실수 ②③) | ❌ 처리 함수·화면 없음 (17번 문서: '새로 추가'). 순서상 '강사 취소·장기 휴가' 단계 맨 앞 (H24(6)③) |
| 수업 결과 입력 (Class Record 대체) | ❌ 강사 화면 시안 전. 운영자 입력 화면도 없음 |
| 학생 수강현황 보기 | ⚠️ 학생 화면 시안 확정(A-1), 실제 데이터 미연결 |
| 정산 | ⚠️ 표(`payroll_items`)만 있음. 화면 없음. **'운영 실수로 못 했지만 강사 지급' 항목 없음** (지금은 상태표대로만 지급 여부가 정해짐) |
| 종료 임박·재등록 | ⚠️ 대시보드 칸만 있음, 데이터 미연결 |
| 기존 학생의 변경권·보강 | ❌ H23(3)대로 이관 안 함 → 재등록 전까지 시트 관리 |

## 3. 제안 순서
0. **(진행 중, 그대로)** 운영 DB 화면(`lms-prod`) → D-52 기존 학생 시간표 입력
   - **질문**: D-52에 '지금 남은 변경권 수'와 '아직 안 잡은·안 끝난 보강'만 추가로 넣을지 (H23(3) 변경 — 대표 결정 필요). 넣지 않으면 기존 학생은 재등록할 때까지 변경권·보강을 계속 시트로 봐야 해서 2·3단계 효과가 재등록 시점까지 늦어짐
1. **취소·변경 처리 (학생 취소 + 강사 취소 공통)** — 이미 승인된 H24(6)③ 위치
   - 운영자가 휴대폰에서 학생 → **실제 예정 수업 목록에서 골라** 취소 → 변경권·보강 가능 여부 자동 판정·차감, 보강 대기 생성
   - 안내문 자동: '10월 29일(목) 오후 5시 수업 → 취소 (보강: …)' 학생용·강사용 각각, [보냈어요] 둘 다여야 완료 (A39 방식 재사용)
   - 되돌리기 (H24(7)), 강사 장기 휴가 = 여러 수업 한 번에 같은 처리
2. **수업 결과 기록 1곳** — Class Record 대체
   - 방식 질문(대표 결정): (가) 강사가 직접 입력하는 최소 강사 화면(오늘 수업 목록 → 상태 버튼 + 다룬 내용) / (나) 당분간 운영자가 LMS에서 입력, 강사는 기존 시트 유지
   - 취소·노쇼는 1단계에서 이미 기록되므로, 여기서 남는 건 '진행함' 표시와 다룬 내용
3. **학생 수강현황 자동** — 방식 질문: (가) 학생 화면 실제 데이터 연결(학생 계정 초대 필요) / (나) 기존 학생 시트를 LMS가 자동으로 채움(학생은 익숙한 시트 그대로)
4. **정산 화면** — 강사별·월별 지급 수업 목록·합계 자동 + '운영 사유 지급' 추가 항목(정책 원본에 규칙 있는지 확인 후)
5. **종료 임박·재등록 감지** — 데이터가 다 있어 작은 작업
6. 그 뒤: D-50 강사 후보 계산, D-42 신청서 가져오기 (신규 주 1명 → 절감 효과가 위보다 작음. H23(2) 순서에서 뒤로 옮기는 것은 대표 결정 필요)
