# 08. 기존 자동화 샘플 분석 (Master · 이지은 · Cindy)

2026-10-16, 세 파일을 **읽기만** 해서 확인(수정 없음). 보조로 같은 실습에서 나온 `Julia_ClassRecord_NEW`, `샘플_이민혁`, `샘플_김하나`의 존재·구조도 확인.
Apps Script와 트리거는 시트에 붙어 있는 형태라 **열어 볼 수 없었음 → '미확인'**. 아래 "스크립트가 한 것으로 보임"은 결과물(값으로 박힌 칸, '업데이트: …' 시각)로 추정한 것.

## 1. 세 파일의 실제 관계

```
                    Master Sheet (운영자)
  시트1: 학생 1명 = 1행 (35칸, 일부 수식) · 강사정보 · 상태매핑표 · 변경신청트래커 · 적립금이력
        │ (IMPORTRANGE, 수식 — 작동 확인)               │ (스크립트로 보임 — 미확인)
        ▼                                               ▼
  Cindy Class Record (강사)                      이지은 수강현황 (학생)
  학생목록(자동) = Master에서 Cindy 학생만         PC 탭: 수강 정보·회차표 (값으로 기록됨)
  상태매핑표(자동) = Master 상태표                 모바일 탭: PC 탭을 수식으로 참조
  시트1: 회차 24행 (값으로 기록됨)                 상태 드롭다운 = Master 상태표 (IMPORTRANGE)
        │                                          수업 노트 링크 = Cindy Student Info (IMPORTRANGE)
        └──── Class Status 기록 → 학생 '진행 여부' 로 가는 연결: 없음 ────┘
```

데이터는 **Master → 강사·학생 한 방향**으로만 흐른다. 강사 기록 → 학생, 변경 신청 → 강사·학생으로 가는 길은 만들어지지 않았다.

## 5. 시트 구조가 복잡해진 이유 (요약)

1. **원본이 여러 개.** 학생 정보는 Master, 회차는 강사 시트, 진행 여부는 학생 시트에 따로 있어 "어느 게 맞는지"가 없음.
2. **복사로 연결.** 파일끼리 값을 복사(스크립트)하거나 끌어옴(IMPORTRANGE). 복사본은 원본이 바뀌어도 따라 바뀌지 않고, 끌어오기는 권한·속도·`#REF!` 문제가 생김.
3. **글자로 연결.** 학생을 이름이나 "이름+요일+시간" 글자로 찾음 → 이름이 같거나 글자가 바뀌면 끊김.
4. **한 행에 이력까지.** 1·2·3차 기간을 한 행의 칸으로 늘려 붙임 → 재등록·24주·연장마다 칸이 모자라고 덮어써야 함.
5. **사람마다 파일 하나.** 학생 N명·강사 M명이면 파일이 N+M개 → 양식 차이가 쌓이고 고칠 때 모든 파일을 고쳐야 함.
6. **규칙이 수식·드롭다운·사람 머리에 흩어짐.** 6시간·변경권 규칙은 트래커(미확인 스크립트), 기간은 수식, 공휴일은 운영자 판단 → 정책이 바뀌면 어디를 고쳐야 할지 모름.
7. **동시 수정 보호 없음.** 두 사람이 같은 시간에 같은 강사 시간을 잡아도 막을 장치가 없음.

이 7가지가 LMS 설계에서 각각 무엇으로 바뀌는지는 [09-design-review.md](09-design-review.md).

## 6. 대표가 공유한 이전 Claude 대화 2건으로 추가 확인한 것 (2026-10-16)

claude.ai 프로젝트 자체는 열 수 없어, 대표가 붙여넣은 대화 내용만 근거로 했다. 스크립트 **전체 코드**는 여전히 보지 못했다(학생 파일 쪽 버튼 코드만 대화에 있음).

### 실제로 있던 스크립트 (미확인 → 일부 확인)

| 위치 | 기능 | 상태 |
|---|---|---|
| Master Sheet 메뉴 `엣지영어 도구 → 학생 시트 자동생성/수정` (`generateStudentSheet`) | Master 학생 행의 값을 **이미 있는** 학생 시트에 채워 넣음 (이지은 시트의 "업데이트: …" 시각이 이것) | 작동. 학생 시트 **파일은 만들지 않음** — 템플릿 사본을 직접 만들고 URL을 Master에 붙여넣어야 함. URL이 비어 있으면 오류 |
| 학생 시트 1차 취소 스크립트 | 회차 체크 → 6시간 판정 → `진행 여부` 칸에 문구 쓰기, 사용 변경권 칸 +1 | 중단·교체. 문제: 지난 수업도 취소됨, 문구가 드롭다운과 달라 오류, **남은 변경권을 두 곳에서 따로 계산**(화면 칸 vs 트래커 건수)해 결과가 다름, 테스트 기록이 트래커에 쌓여 계산을 틀어지게 함 |
| 2차 구조: 학생 파일 버튼 → Master **중계 웹앱** | 학생이 날짜 칸 선택 → 버튼 → Master 웹앱이 미리보기·판정·트래커 기록·학생 시트 기록·메일 처리 (판정 규칙은 Master 한 곳) | 웹앱 배포까지 완료, 학생 파일 버튼 설치·테스트는 진행 중이었음. 같은 시기 화면에 "트래커 비어 있음", "변경권 -2회 / 총 회" 오류 |

2차 구조는 "규칙은 한 곳에서만 판정"이라는 방향이 LMS 설계와 같다. 차이는 **누가 요청했는지 확인하는 방법**이다.

### 2차 구조의 보안 문제 (실제 학생에게 쓰기 전 반드시 해결)

1. **공용 비밀값이 학생 파일 안에 있음.** 학생 파일의 Apps Script에 Master 웹앱 주소와 공용 토큰이 그대로 들어간다. 학생 파일을 편집할 수 있는 사람은 확장 프로그램 → Apps Script에서 볼 수 있다. (이 저장소·문서에는 토큰 값을 옮기지 않았다. 대화 기록에는 남아 있으므로, 이 방식을 계속 쓴다면 토큰을 새로 바꾸는 것을 권한다.)
2. **학생 번호를 학생 파일의 A1 칸에서 읽음.** 학생이 A1을 다른 Student ID로 바꾸면 다른 학생 수업을 취소 요청할 수 있다. Master 쪽 코드가 "보낸 파일 ID = Master에 등록된 그 학생의 시트 주소"인지 확인한다면 막히지만, Master 코드를 보지 못해 **확인 불가**.
3. 학생이 버튼을 쓰려면 학생 시트 **편집 권한**과 Google의 "확인되지 않은 앱" 권한 허용이 필요하다 → 학생이 시트의 다른 칸도 고칠 수 있다.

LMS에서는 로그인한 사람만, 서버가 그 사람의 수업인지 확인한 뒤 처리하므로 이 세 가지가 구조적으로 없다(권한 테스트 포함).

### 정책·설계에 반영할 점

- **상태 문구가 세 가지로 갈라짐**: 코드 "학생 늦은 취소" / 학생 시트 드롭다운 "학생 늦은 취소 👉 보강 없음" / Master 상태매핑표 "학생 늦은 취소 👉 보강 불가" (정상 취소도 "보강 가능" vs "수강기간 내 보강 가능"). 글자로 연결해서 생기는 문제 → LMS는 상태 코드로 연결하고 학생 문구는 표 한 곳에서만 가져옴.
- **규모**: 강사 1명당 학생 10명 이하(프리랜서). 강사 화면·빈 시간 계산을 단순하게 유지해도 됨.
- **학생 탭을 강사 파일 하나에 모으는 안은 이미 기각**(탭 숨기기는 보안이 아님). LMS의 사람별 권한 설계와 같은 판단.
