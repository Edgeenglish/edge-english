## 2. '학생 무응답' 처리 — 안전한 방식 제안 (대표 결정 필요)

이번 사고의 원인은 "다음 주 목요일"을 사람이 해석하다 다른 주로 고른 것. AI 해석 없이 **화면이 모호함을 드러내게** 하는 것이 핵심.

**공통 (해석 보조, AI 아님)**: 운영진이 요일만 고르면 화면이 '카톡 받은 날' 기준으로 그 요일의 다가오는 수업을 날짜와 함께 나란히 보여 줌 — 예: 일요일 카톡이면 `① 10/23(목) 이번 주` `② 10/30(목)` `③ 11/6(목)`. 운영진은 그중 하나를 **직접 누름**. 학생 말에 날짜(10/30)가 있으면 '명확', '다음 주'처럼 요일만 있으면 주말에 받은 메시지는 자동으로 '모호 가능' 표시.

**모호할 때 (두 수업 이상으로 읽힘)**
1. 아무 수업도 취소하지 않고 '확인 필요'로 저장. 확인 문구 자동 생성: "10/30(목) 17:00 / 11/6(목) 17:00 중 어느 수업인가요? 1 또는 2로 답해 주세요."
2. 답 기한 = **가장 빠른 후보 수업 시작 24시간 전** (그 전에 처리할 일 맨 위로)
3. 기한까지 무응답이면 두 안 중 선택:

| | A. 가장 빠른 후보를 취소 (추천) | B. 아무것도 취소 안 함 |
|---|---|---|
| 처리 | 가장 빠른 후보를 학생 정상 취소로 처리. 6시간 판정은 **원래 카톡 시각** 기준(학생에게 불리하지 않게). 늦은 후보는 그대로 | 두 수업 모두 그대로 |
| 안내 | 학생·강사 **둘 다**에 정확한 날짜 안내. 학생: "답이 없어 10/30(목) 17:00 수업을 취소했어요. 다른 날짜였다면 바로 말씀해 주세요 — 되돌리고 변경권도 돌려드려요." | 학생에게 "확인이 안 돼 두 수업 모두 그대로 진행돼요" 안내 |
| 장점 | 강사가 기다리는 사고는 **가장 가까운 수업**에서 남. 늦은 후보는 정정할 시간이 남음 | 학생 뜻과 다른 취소가 생기지 않음 |
| 위험 | 학생이 실제로는 늦은 날을 뜻했고 안내도 안 읽으면, 가까운 수업에 학생이 들어왔는데 강사 없음 → 운영 처리로 보고 **무료 복구(보강)** | 학생이 안 들어올 가능성이 큼 → 강사 대기·학생 노쇼(1회 소진). 이번 사고와 같은 모양 |

**명확할 때**: 요청서대로 되묻지 않고 처리 + 날짜를 넣은 안내("요청하신 10월 29일(목) 오후 5시 수업이 취소 처리되었습니다. 요청하신 날짜와 다르다면 바로 말씀해 주세요.").

**요청 시각이 불명확할 때**(카톡 시각을 못 찾음 등): 6시간 경계에 걸리는 경우만 '확인 필요'. 경계에서 먼 경우(예: 수업 3일 전)는 그대로 처리. 운영진이 넣은 요청 시각은 입력 시각보다 늦을 수 없고, 입력자와 함께 이력에 남음.

## 3. 반영 단계 제안

H23 순서(운영 DB ✅ → D-52 간단 입력 → **강사 취소·장기 휴가 화면** → D-50 → D-42)는 **그대로**. 취소 처리의 핵심(수업 취소·변경권·보강·안내·되돌리기)은 강사 취소와 **같은 엔진**이므로, '강사 취소·장기 휴가' 단계의 **앞부분**으로 넣는 것이 중복이 없음.

| 단계 | 넣을 것 |
|---|---|
| **①** '강사 취소·장기 휴가' 단계 앞부분 (H23 3번째) | ① 공통 취소 함수(수업 잠금·규칙 검사·변경권·이력, `via`로 학생/운영진/강사 구분, **카톡 요청 시각** 칸) ② **운영진 대신 처리 화면**(학생 검색 → 예정 수업 목록 → 직접 선택 → 결과 미리보기 → 확정), 휴대폰 우선 ③ **취소·보강 안내 기록 표** + 문구 자동 생성(`기존 수업: 10/29 (Thu) 17:00 KST → 보강 수업: 10/30 (Fri) 17:00 KST`) + 학생·강사 각각 [복사] → [보냈어요], 둘 다 보내야 완료(A39와 같은 방식) ④ 보강 입력(강사가 가능하다고 한 뒤 운영진이 확정 — D-43) ⑤ **되돌리기**(수업 복구·변경권 복구·보강 취소·정정 안내) ⑥ 중복 방지 DB 제약 추가 + 아래 결함 수정 ⑦ '확인 필요' 처리할 일. 전제: 학생 목록·상세 실제 데이터 연결 |
| 　 이어서 같은 단계 | 강사 취소(6시간 기준·2,000원 적립 A16)·장기 휴가 일괄 처리 — 위 엔진 재사용 |
| **②** 4단계 학생 셀프서비스 | 학생 화면 실제 연결: 지금 확인창 + D-45 두 갈래(다른 시간 신청 / 빼기만). 같은 DB 함수 |
| **③** 5단계 자동 발송 | 학생 이메일·강사 Google 캘린더 자동 반영(A33)이 [복사]→[보냈어요]를 대신. 그 전까지는 수동 |

**⑤ 설계 결함 (①에서 함께 수정)**: `credit_ledger`의 `unique(수업, 사유)` 때문에 "잘못 취소(차감) → 되돌림(복구) → 같은 수업을 나중에 진짜로 취소" 하면 두 번째 차감이 DB에서 거절됨. 되돌린 수업은 다시 정상 취소할 수 있어야 하므로, 중복 방지 기준을 '수업'이 아니라 **'요청(change_request) 1건당 1번'**으로 바꾸는 것이 맞음. 지금 운영 DB에는 이 표를 쓰는 데이터가 없어(학생 0명, 차감 기록 0) 바꾸기 쉬운 시점.

**1주일 시험과의 관계 (참고)**: 1주일 시험 동안 실제 학생 시간표가 LMS에 들어가지만 취소 입력 기능은 아직 없음 → 그 주의 취소·보강은 지금처럼 시트·카톡으로 하고, LMS 시간표는 취소된 수업이 그대로 남아 시트와 달라질 수 있음. 시험 기간에는 시트가 원본이므로 문제는 없지만, **본격 사용(시트 기록 중단) 전에 ①이 끝나야** 함.
