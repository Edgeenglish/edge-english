홈페이지 회원가입·로그인 시안 (1단계)

정책 원본 H26(146) · 아이디 = 이메일 · 비밀번호 로그인 · 기존 학생·강사는 재가입 없이 비밀번호만 만들기. 코드·DB·로그인 설정은 바꾸지 않았습니다.

대표 결정 7개

  1. ① 아이디 = 이메일로 확정할까요?추천: 이메일 · 학생 1,000명 넘어도 그대로 씀. 따로 아이디를 만들면 '아이디 찾기' 화면이 하나 더 생김
  2. ② 가입 칸: 이름·이메일·비밀번호 + 약관 동의 2개만 받을까요?추천: 이것만 · 휴대폰·생년월일은 받지 않음(수강신청서에서 받음, 개인정보 최소)
  3. ③ 비밀번호 최소 길이는 몇 자로 할까요? 숫자라 대표 결정 · 선택지: 6자(Supabase 기본) / 8자(추천, 흔한 기준) / 10자. 시안 글자 '○자 이상'은 정해지면 바꿈
  4. ④ 가입할 때 이메일로 온 6자리 코드를 한 번 넣게 할까요?추천: 넣음 · 남의 이메일·오타 이메일로 가입하는 것을 막음. 안 넣으면 비밀번호 찾기 메일이 엉뚱한 곳으로 감
  5. ⑤ 기존 학생·강사의 첫 비밀번호 = '비밀번호 찾기'와 같은 화면으로 할까요?추천: 같은 화면 '비밀번호 만들기·찾기' · 이메일 → 메일 코드 → 새 비밀번호. 지금 쓰는 '메일 코드로 로그인'은 로그인 화면에서 뺌(화면 하나 줄임)
  6. ⑥ 카카오 로그인을 이번에 같이 넣을까요?추천: 이번엔 빼고, 같은 로그인 화면 맨 위에 나중에 추가 · 카카오는 대표의 카카오 개발자 앱 등록이 먼저 필요해 11/14(H26(128))에 맞추기 어려움. 11/9 카카오 시안 결정(첫 연결은 '내 정보'에서만)은 그대로 이어 씀
  7. ⑦ 홈페이지 위 말풍선 '회원가입 없이 간편 신청하기'를 없앨까요?추천: 없앰 · 옆에 [로그인]이 생기면 말이 엇갈림. 수강신청은 지금처럼 구글폼(가입 없이도 신청 가능)은 그대로

흐름

홈페이지 [로그인]›이메일 + 비밀번호›권한별 홈 (학생·강사·운영자)
새 회원: [회원가입]›이름·이메일·비밀번호›메일 코드›가입 끝 → 로그인된 채 홈
기존 학생·강사: [비밀번호 만들기·찾기]›이메일›메일 코드 + 새 비밀번호›지금 계정·기록 그대로
운영자›이메일 + 비밀번호›인증 앱 코드 (지금과 같음)
