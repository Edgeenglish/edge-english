홈페이지 결제 연동 비교안

정책 원본 H26(179) 첫 단계 · 2026-11-14 · 개발은 대표 승인 뒤. 미확인 표시는 나이스페이·업체 확인 전 값입니다.

대표 결정 4가지

  1. 결제 방식
    B. 나이스페이 직접 연동 (권장) / C. 토스페이먼츠 새 계약 / D. 포트원 + 나이스페이
  2. 계좌이체
    대표 계좌 직접 입금 유지 (권장) — 운영진이 입금 확인 버튼 1번 / 가상계좌 — 입금 자동 확인, 건당 수수료 미확인
  3. 결제 전 로그인
    필수 (권장) — 결제가 학생 계정에 바로 붙어 자동 등록 가능, 카카오 버튼 1번 / 비회원 결제 — 결제 뒤 운영진이 학생과 연결
  4. 나이스페이 확인 메일
    아래 '먼저 확인할 것' 7가지를 Claude가 support@ 메일로 나이스페이에 문의 — 대표 '보내' 뒤 발송

지금 사실 (support@ 메일·운영 DB 확인)

  • 나이스페이 계약: 2026-01 아임웹 연동형 OK전자계약 · 상호 '탠저린 영어' · 등록 주소 tangerineenglish.imweb.me · 업종 '영어 전자책' · 디지털 상품이라 보증보험 필수(월 정산한도 = 보험 가입금액)
  • 지금 결제 순서(POL-PAY-02): 아임웹 카드 링크 또는 계좌이체 → 구글폼 신청서 → 카카오톡 채널 → 운영진이 LMS에 결제 직접 입력
  • 운영 DB 결제 기록 4건: 카드 1 · 계좌이체 3 (11/7 LMS 오픈 뒤 기록분만이라 비율 판단엔 부족) · 학생 13명 중 해외 시간대 3명
  • 정책 기준표 POL-PAY-07 '새 PG·결제 시스템을 만들지 않음'은 H26(179)와 다름 → 승인되면 기준표를 고칩니다

위험H26(179)와 반대 방향아임웹 연동형 계약을 직접 연동에 못 쓰면 새 상점 아이디·심사 필요계약을 처음부터 다시업체 하나 더 의존. PG를 여러 개 쓸 계획이 없으면 이점 작음

권장 이유: 이미 계약·심사를 거친 나이스페이를 쓰면 새 계약 비용·기간이 가장 적고, 중간 업체(D) 없이 Vercel 서버 + Supabase로 바로 연결됩니다. 나이스페이 확인 결과 새 계약이 필요하면 그때 C와 다시 비교합니다.

먼저 확인할 것 (나이스페이, 개발 전)

  1. 아임웹 연동으로 받은 상점 아이디를 자체 홈페이지(edgeenglish.kr) API 결제에 그대로 쓸 수 있는지, 새 상점 아이디가 필요한지
  2. 등록 주소 변경(아임웹 → edgeenglish.kr) 절차·심사 기간
  3. 업종 '영어 전자책' → '화상영어 수업'·상호 '탠저린 영어' → 엣지영어 변경 필요 여부
  4. 지금 계약 카드 수수료율·정산 주기
  5. 보증보험 가입 상태와 월 정산한도 (넘으면 정산 보류)
  6. 카카오페이·네이버페이가 결제창에 포함되는지
  7. 해외 발급 카드 결제 가능 여부 (해외 거주 학생용)
