# 07. 운영자가 결정해야 할 사항

정말 운영자만 정할 수 있는 것(수업 횟수, 학생 권리, 급여, 개인정보, 비용)만 모았다. 기술적인 선택은 이미 정해서 05·06 문서에 반영했다.
각 항목의 '추천'은 제안일 뿐이며, 결정 전에는 코드에 적용하지 않는다 (코드에서 값이 비어 있으면 동작하지 않게 막아 둠).

상태: ⬜ 미결정 · ✅ 결정 (결정되면 날짜와 함께 여기 기록)

## 먼저 정해야 할 것 (2단계 개발 전)

| # | 질문 | 선택지 | 추천 | 이유 |
|---|---|---|---|---|
| D-1 ⬜ | **재등록 이월 기한** + 재등록 대기(시간 맡아 두기) 기간 | ① 종료일 당일 23:59 (FAQ·안내서) ② 다음 날 23:59 (PDF) ③ 종료 후 7일 (수강계약서) | **③ 7일, 대기 기간도 7일로 통일** | 학생이 동의한 계약서와 같아 분쟁 위험이 가장 낮음. 이월 기한과 시간 맡아 두기 기간이 같으면 규칙이 하나로 줄어듦. 단점: 강사 시간이 최대 7일 비어 있을 수 있음. ①·②를 고르면 계약서도 함께 고쳐야 함 |
| D-2 ⬜ | **확정된 보강을 다시 취소**하면 | A. 재보강 불가, 수업 1회 소진 (FAQ 현재 문구) B. 정규 수업과 똑같이 (변경권 사용 후 다시 보강) | **A** + 새 상태값 `Make-up canceled (no rebook)` 추가 (수업 소진 Y, 변경권 N, 강사 급여 N) | 이미 학생에게 공지된 내용이고 보강이 끝없이 밀리는 것을 막음. 6시간 전에 알렸으니 강사 급여는 미지급이 공정. 강사 노쇼 보상 수업도 같은 규칙 적용 추천 |
| D-3 ⬜ | **학생 장기 연기** (FAQ·계약서·PDF 모두 다름) | ① FAQ: 3개월 최대 1주, 6개월 최대 2주 ② 계약서: 6개월만 최대 4주 1회 ③ PDF: 24주만 최대 2주 | **②를 기준으로 하되 현재 계약서 그대로 적용** (24주만, 최대 28일, 수강기간 중 1회, 증빙, 수업 24시간 전 요청) | 학생이 동의한 문서 기준. FAQ·상태 문구만 계약서에 맞춰 고치면 됨. 바꾸고 싶다면 새 계약서부터 적용 |
| D-4 ⬜ | **'공휴일'로 볼 날** (변경권 차감 없음) | ① 법정 공휴일(대체공휴일 포함)만 ② ①+운영자가 추가하는 날(예: 노동절) | **②** — 운영자가 1년 치를 관리 화면에 등록 | 공지에 노동절이 예시로 있어 법정 공휴일만으로는 부족. 등록 방식이면 매년 바뀌어도 코드 수정 없음 |
| D-5 ⬜ | **로그인 방식** | 이메일 6자리 코드 / 카카오 / 개인 링크 | **학생·강사 이메일 코드, 운영자 Google** | 무료, 심사 없음, 휴대폰에서 쉬움. 개인 링크는 링크가 새면 끝이라 비추천. 카카오는 나중에 추가 가능 |
| D-6 ⬜ | **비용 승인** (실제 운영 시작 때) | Supabase Pro $25/월 (+ Vercel이 Hobby면 Pro $20/월) | **개발 중 $0, 시범 운영 시작 때 Supabase Pro 결제** | 무료 요금제는 백업이 없고 1주 미사용 시 멈춤 → 실제 학생 데이터에는 부적합. Vercel 현재 요금제를 알려 주세요 |

## 보류 (지금 결정 불필요, 자동화하지 않음)

- **환불**: 계산 자동화 없음. 운영자가 금액 입력·승인만. 단, 현재 FAQ·수강계약서는 학원법 기준을 공지 중이므로, '수수료만 공제' 방식으로 바꾸려면 문구 변경과 법적 확인이 먼저.
- 카드 결제를 아임웹에 둘지 자체 결제로 바꿀지 → 나중.
- 휴식 중인 강사의 후기 → 후기에 강사명을 표시하지 않으므로 **해당 없음 (결정 불필요)**.
- 적립금 기능 범위, 체험수업 칼럼 정리 → 나중.

## 시안 선택 (화면 개발 전)
- 2단계에서 만들 **운영자 대시보드**와 **신규 학생 등록** 화면 시안을 각 3개씩 준비함. 미리보기에서 하나씩 골라 주세요.
- 학생 화면·강사 화면 시안은 3·4단계 시작 전에 따로 준비 (먼저 만든 화면에서 배운 점을 반영하기 위해).
