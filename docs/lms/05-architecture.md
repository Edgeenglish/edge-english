# 05. 최종 기술 구조

## 한눈에 보기

```
 학생(휴대폰)   강사(휴대폰·PC)   운영자(휴대폰·PC)
      │               │                 │
      └──── edgeenglish.kr (Next.js, Vercel) ────┐
             /my      /tutor      /admin           │  기존 홈페이지·수업료·후기는 그대로
                     │                             │
            서버(규칙 검사 · 권한 확인 · 한 번에 저장)
                     │
            Supabase (PostgreSQL = 유일한 원본, 로그인)
                     │
      ┌──────────────┼───────────────┐
  Google 캘린더     이메일 발송       Google 시트
  (강사별 보조 캘린더  (Resend)       (보고·검증용 내보내기,
   — 복사본)                          이관 원본)
```

| 구성 | 선택 | 이유 |
|---|---|---|
| 화면 | 기존 Next.js 프로젝트 안에 `/my`(학생) `/tutor`(강사) `/admin`(운영자) 추가 | Vercel 프로젝트 1개만 관리. 홈페이지와 디자인·도메인 공유. 별도 브랜치·미리보기 주소에서 확인 후 합침 |
| DB·로그인 | Supabase (서울 리전) | PostgreSQL + 로그인 + 권한(RLS) + 예약 작업(pg_cron)이 한곳에 있어 관리 대상이 적음 |
| 규칙 계산 | TypeScript 한 곳 (`src/lms/rules/`) | 규칙이 한 벌만 있어야 고치기 쉬움. 자동 테스트로 검증 |
| 최후 방어선 | DB 제약 (`supabase/migrations/`) | 화면·서버에 실수가 있어도 겹치는 수업, 두 번 차감, 기록 삭제가 DB에서 막힘 |
| 수강후기 | 지금 Apps Script 그대로 | 이미 완성, LMS와 섞을 이유 없음 |

## 데이터 구조 (요청하신 15개 항목 → 실제 표)

> **v0.2 (2026-10-16 오후) 변경**: 가격표·설정 표 삭제(정책 값은 기준표 + 코드 한 곳), 계약 판본(`terms_versions`)·강사 계약(`tutor_contracts`) 추가, 단계별 4개 파일로 분리, 연장 장부 자동 합계. 자세한 이유와 기존 시트 연결표는 [09-design-review.md](09-design-review.md).

시트 컬럼을 그대로 옮기지 않고 "한 가지 사실은 한 곳에만" 원칙으로 정리했다. 전체 정의: `supabase/migrations/20261016000000_lms_core.sql`

```
students ─┬─ enrollments ── enrollment_periods ── credit_ledger
(STU-xxxx)│   (1차·2차 등록)   (28일 기간·변경권 지급)   (변경권 사용·복구 한 줄씩)
          │        │
          │        ├── payments ── refunds (금액 수동 입력·승인만)
          │        └── enrollment_extensions (장기 연기·강사 휴무 연장 사유)
          │
          ├─ regular_schedules (고정 요일·시각, 바뀌면 새 행 → 이력)
          │
          └─ lessons ─┬─ class_records (Covered Topics·Remarks·최초 기록 시각)
             (모든 회차)├─ change_requests (모든 변경·취소·일괄 처리 기록)
                      ├─ makeup_requests ── makeup_candidates
                      ├─ compensations (강사 노쇼 보상 수업권)
                      ├─ no_show_reports ('강사가 안 들어왔어요')
                      ├─ calendar_sync (캘린더 반영 상태)
                      └─ payroll_items ── payroll_runs ── pay_policies(승인된 급여 기준)

tutors ── tutor_availability (주간 가능 시간, 강사 현지 시각) · tutor_time_off (막은 날·휴무)
공통: holidays(변경권 면제 공휴일) · settings(규칙값) · notifications · audit_log(모든 변경 이력)
     · class_status_rules(상태매핑표 14개) · price_list(4주 정가표)
```

| 요청 항목 | 표 | 정리한 점 |
|---|---|---|
| Students | `students` | Student ID(`STU-0001`) 영구 고유번호. 재등록해도 같은 학생 행 사용 |
| Tutors | `tutors` | 고정 시차(+2) 대신 IANA 시간대 |
| Enrollments | `enrollments` + `enrollment_periods` | 시트의 '1·2·3차 시작·종료일' 칸 → 등록 1건 = 1행, 기간 1개 = 1행 (24주 6기간 지원). 재등록은 새 등록 행 + `previous_enrollment_id` |
| Regular Schedules | `regular_schedules` | 시간 변경 시 덮어쓰지 않고 새 행 → 언제부터 바뀌었는지 남음 |
| Lessons | `lessons` | 정규·보강·보상 모두 한 표. 예정 수업은 진행 여부와 관계없이 남음(삭제 금지) |
| Class Records | `class_records` + `lessons.class_status` | 결과 상태는 `lessons`에 한 곳만. 시스템이 아는 취소는 자동 기록 → 강사는 진행 수업만 기록 |
| Change Requests | `change_requests` | 학생·강사·운영자 대리·일괄 처리 모두. 규칙 검사 결과를 같이 저장 |
| Make-up Requests | `makeup_requests` | 희망 시간 2~3개, 강사 확정/다른 시간 제안 |
| Change Credits | `enrollment_periods.credits_granted` + `credit_ledger` | 남은 개수를 칸에 덮어쓰지 않고 '사용 1줄'씩 기록 → 남은 개수 = 지급 − 사용 |
| Compensation / Coupons | `compensations` | 운영자 확정 필수, 사용 기한은 결정 후 입력 |
| Payments | `payments`(실제 입금 기록), `refunds` | 결제할 금액은 등록에 한 곳. 환불 금액 자동 계산 없음 |
| Tutor Payroll | `tutor_contracts`, `pay_policies`, `payroll_runs`, `payroll_items` (6단계 파일) | 강사별 계약 판본·시급. 승인된 급여 기준이 없으면 계산 안 함. 같은 수업 두 번 정산 불가. 최종 금액은 운영자 승인 |
| Availability | `tutor_availability`, `tutor_time_off` | |
| Notifications | `notifications` | 같은 알림 두 번 금지(dedupe_key), 성공·실패 기록 |
| Audit Logs | `audit_log` | 모든 표의 변경 전·후 자동 기록, 수정·삭제 불가 |

## 반드시 보장해야 할 것 → 어떻게 보장하나

| 요구 | 방법 | 검증 |
|---|---|---|
| 데이터 원본 일원화 | 학생·강사·운영자 화면이 같은 `lessons` 표를 읽음. 시트·캘린더는 DB에서 만든 복사본 | 설계 |
| 학생별·강사별 접근 권한 | DB 권한(RLS): 학생은 본인 것만, 강사는 담당 수업만, 학생 정보는 필요한 칸만 함수로 제공. 앱 사용자는 **읽기만**, 쓰기는 서버만 | `supabase/tests` 권한 14개 항목 (A학생이 B학생 보기, 강사가 다른 강사 학생 보기 등) |
| 동시 예약·중복 수업 방지 | `lessons` 에 강사별·학생별 시간 겹침 금지 제약 (취소된 수업 제외). 두 학생이 같은 시간을 동시에 확정해도 DB가 하나만 받음 | 테스트 통과 |
| 변경권 중복 차감 방지 | `credit_ledger` unique(수업, 사유) + 기간 행 잠금 + 0개 미만 금지 | 테스트 통과 |
| 기록 삭제 없이 이력 보존 | 수업·기록·장부 삭제 금지 트리거, 모든 변경 `audit_log` (수정·삭제 불가) | 테스트 통과 |
| 시간대·서머타임 | 시각은 `timestamptz`(UTC)로 저장, 고정 수업 시각은 KST(서머타임 없음)로 저장, 화면에서만 학생·강사 IANA 시간대로 변환. 강사 가능 시간은 강사 현지 시각+시간대로 저장 | 시드니·브리즈번·토론토 서머타임 전환 테스트 |
| 정책·기간 계산은 KST | 날짜 계산은 한국 날짜(`date`)로만, 6시간 기준은 실제 시점 차이 | 테스트 |
| 변경 처리의 원자성 | 서버에서 한 트랜잭션: [수업 잠금 → 규칙 검사 → 상태 변경 → 변경권 기록 → 보강/알림/캘린더 대기열 → 이력] 중 하나라도 실패하면 전부 취소 | 2단계 개발 시 통합 테스트 |
| DB↔캘린더 동기화 오류 | 수업이 바뀌면 같은 트랜잭션에서 `calendar_sync` 대기열에 올림 → 별도 작업이 반영·재시도. 실패해도 수업 변경은 유지되고 관리자 화면에 '캘린더 반영 실패 N건 [다시 시도]' 표시. 매일 밤 전체 대조 | 테스트(대기열 등록) |
| 보안·백업·복구 | 아래 '보안·백업' 참고 | |

## 시간 처리 규칙 (요약)

1. 정규 수업 시각은 **한국 시각**으로 고정 저장 (예: 화 17:00 KST). 한국은 서머타임이 없어 날마다 같은 UTC 시각이 됨.
2. 해외 학생·강사 화면은 각자의 시간대로 변환해 보여 줌 → 서머타임이 바뀌면 현지 시각이 1시간 움직이는 게 정상 (PDF의 '서머타임 7일 전 안내'가 필요한 이유).
3. 6시간 기준·보강 기한(종료일 23:59)·공휴일 판정은 모두 KST.
4. 강사의 '수업 가능 시간'은 강사가 사는 곳 기준으로 저장 (강사에게 자연스러움) → 보강 후보 계산 시 KST로 변환.

## 로그인·권한

| 사용자 | 추천 방식 | 이유 |
|---|---|---|
| 학생 | **이메일 6자리 코드** (비밀번호 없음). 한 번 로그인하면 휴대폰에서 오래 유지 | Supabase 기본 기능, 추가 비용·심사 없음. 카카오 로그인은 카카오 개발자 앱 등록·심사가 필요해 나중에 추가 가능 |
| 강사 | 이메일 6자리 코드 (영어 화면) | 학생과 같은 방식이라 관리 단순 |
| 운영자 | Google 로그인 (support@edgeenglish.kr, 2단계 인증 필수) | 기존 Google 계정 보안 그대로 사용 |

- 회원가입 버튼 없음. **운영자가 등록한 이메일만 로그인 가능** → 모르는 사람이 가입할 수 없음.
- 학생은 Student ID를 입력할 일이 없음. 로그인한 이메일 = 본인 확인.

## 기존 시트 데이터 이관

1. **읽기만**: Master Sheet·Class Record·학생 시트에서 필요한 값을 내려받음 (원본 수정 없음). 내려받은 파일은 GitHub에 올리지 않음.
2. **변환**: 이름으로 연결된 기존 Class Record 행을 Student ID에 맞춤. 맞지 않는 행은 목록으로 뽑아 운영자 확인.
3. **시험 DB에 넣기** (운영 DB 아님) → 학생별 검증표 자동 생성: 등록 회차·진행 회차·남은 회차·남은 변경권·종료일을 시트 값과 나란히 비교, 다르면 빨간색.
4. 운영자가 검증표 확인 → **승인 후** 운영 DB에 넣음.
5. 범위: 현재 수강 중인 등록 + 그 등록의 지난 수업. 끝난 옛 등록은 요약(몇 차, 기간, 금액)만.
6. 전환 후 시트는 읽기 전용 보관 + DB에서 매일 보고용 시트 내보내기 (문제가 생기면 시트로 되돌아갈 수 있게).

## Google 캘린더 연동

- 방식: Google **서비스 계정**(로봇 계정)에 강사별 보조 캘린더 '일정 변경' 권한을 공유. 운영자 계정 비밀번호를 시스템에 넣지 않음.
- **DB가 원본, 캘린더는 복사본.** 시스템은 자기가 만든 일정만 고치고, 강사 개인 일정은 '바쁨'으로 읽기만 함.
- 일정 ID를 수업 ID로 만들어서, 재시도해도 같은 일정이 두 번 생기지 않음.
- 실패 시: 자동 재시도 → 그래도 실패하면 관리자 화면에 표시. 매일 밤 DB와 캘린더 전체 대조.
- 켜는 순서 (PDF 11-2 유지): 처음에는 캘린더에 쓰지 않고 '반영될 내용'만 비교 → 이상 없으면 켬.
- 운영자 할 일(그때 안내): Google Cloud에서 서비스 계정 1개 만들기, 강사 캘린더 공유 설정. 비용 없음.

## 알림

- 이메일 기본 (학생 한국어, 강사 영어, 운영자 사본). 발송 서비스 Resend.
- 개발·시험 중에는 **모든 메일을 support@edgeenglish.kr 로만** 보내는 안전 모드. 실제 발송은 승인 후 켬.
- 운영자 할 일(그때 안내): 도메인 DNS에 발송 인증 기록 추가 (스팸함 방지).
- 카카오 알림톡·왓츠앱: 발송 대행 계약 필요 → 나중.

## 정기 작업 (기록 독촉, 재알림, 캘린더 재시도 등)

- Supabase 예약 작업(pg_cron)이 5분마다 서버의 보호된 주소를 호출. Vercel 요금제와 관계없이 동작.
