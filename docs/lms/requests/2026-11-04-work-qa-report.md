- **수정 지시:** `LessonChange.tsx`의 `MakeupRow`/`localTime`에서 입력 중 날짜를 곧바로 `tutorLocalLabel`에 넘기지 마세요. 완성된 날짜·허용 범위를 확인한 뒤 변환하고, 변환 실패는 해당 입력란의 오류로 처리하세요. 다른 보강 날짜·휴무·일정 수정 날짜도 같은 입력 방식으로 재시험하세요.
- **데이터 영향:** 잘못된 날짜는 저장되지 않았고 새로고침으로 화면을 복구했습니다.

### QA-17. 잘못 등록한 휴무 자체를 취소하는 화면 경로가 없음

**보통 / 배포 전 보완 권장 / 실제 등록·대체 취소·보강 정리 + 코드 검토**

- **재현:** 관리자 → 강사 휴무 → 가상 Blair의 11/5 휴무 등록 → 임수아 대체 배정 → 다시 고르기 → 기존 강사 보강 → 다시 고르기를 확인했습니다. 강사 Schedule에서 해당 Leave도 직접 열었습니다.
- **기대:** 날짜나 강사를 잘못 골랐거나 휴무가 취소되면, 영향을 확인하고 휴무 등록 자체를 철회하는 경로가 있어야 합니다.
- **실제:** `다시 고르기`는 대체·보강 선택만 초기화합니다. 휴무와 처리할 일은 남습니다. 강사 Leave 상세도 `This time is in your leave.`와 Close만 제공하며 휴무 취소 경로가 없습니다. 일반 개인 일정의 Remove block과 다릅니다.
- **추가 확인:** 보강을 먼저 정리하고 다시 고르기를 누르면 원래 수업은 scheduled로 돌아오지만, 휴무 기간과 `대체 강사 고르기 필요`는 남습니다. 휴무를 완전히 철회한 상태가 아닙니다.
- **수정 지시:** 운영진에게 휴무 철회 경로를 제공하세요. 영향받는 정규·확정 대체·보강·자동 연장·안내 기록을 미리 보여 주고 일관되게 정리해야 합니다. 과거 수업이나 이미 완료된 수업을 무조건 되돌리지 말고, 처리 제한과 감사 이력을 남기세요. 기존 A안의 학생 선택 정책은 유지하세요.
- **근거:** 관리자 휴무 화면과 `admin_leave_back`은 선택 단계 복구만 지원합니다. 이 검증에서는 SQL로 휴무를 강제 삭제하지 않았습니다. 시험 휴무 1건은 아래 기록대로 남아 있습니다.
