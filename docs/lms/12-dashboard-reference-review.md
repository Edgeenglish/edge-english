# 12. 대시보드 참고 이미지 검토 (2026-10-17)

대표가 준 학생용·운영자용 참고 시안 2장(실제 화면 아님)에서 **쓸 만한 요소만** 골라 기존 설계와 비교한다. 이미지를 그대로 만들지 않는다. 이미지 속 날짜·횟수·정책 문구는 예시일 뿐이고, 기준은 정책 원본과 기준표다.

- 운영자 대시보드 **A안(처리할 일 중심, H01 확정)과 지금 코드는 그대로** 유지한다(`src/app/lms/admin/`, `src/lms/admin/board.ts`).
- 도넛 차트·복잡한 통계·중복 요약 카드·장식 요소는 넣지 않는다.
- 새 주요 화면(학생 메인 등)은 **구성이 다른 시안 3개 → 대표 선택 → 구현**(B06). 이 문서는 시안을 만들 때 쓸 재료 목록이다.

## 1. 운영자 화면

| 이미지 요소 | 지금 A안·DB | 판단 |
|---|---|---|
| 신규 학생 매칭 대기 | ✅ 있음 (`new_student_matching`, 3영업일 기한·임박/초과) | 그대로 |
| 재등록 강사 확인 대기 | ✅ 있음 (`renewal_tutor_notice`, 강사 [확인]·일정 조치 추적) | 그대로 |
| 강사 노쇼 신고 / 오늘의 수업 | ✅ 있음 (노쇼 신고 최우선, 오늘 수업 목록) | 그대로. 이미지의 '학생 노쇼·강사 노쇼' 상태 표시는 오늘 수업 목록의 상태 글자로 이미 표현 |
| 장기 연기 신청 승인 | ✅ 있음 (`long_leave_request`) | 그대로 |
| **보강 신청 — 강사 확인 대기** | DB 있음(`makeup_requests` requested/countered), 대시보드 항목 없음 | **추가 (낮은 비용)**: 강사 무응답 기준(D-11)이 정해지면 처리할 일에 1종 추가 |
| **보강 강사 미확인** (확정·변경·취소된 보강을 강사가 LMS에서 [확인] 안 함) | 없음 | **추가 (누락 방지, 대표 지시 2026-10-17)**: 강사 LMS [확인] 추적의 운영자 쪽 표시. 이메일과 무관, 확인 기한은 미정 |
| **캘린더 반영 실패** | DB `calendar_sync` 있음, 화면 없음 | **추가 (캘린더 연동 때)**: 재시도 후에도 실패·매일 대조 차이 |
| **보강 미신청 학생** ("취소 후 n일째 보강 안 잡음") | 데이터로 계산 가능(취소된 수업 − 잡힌 보강, 수강기간 내 보강 기한 POL-PER-06) | **추가 권장**: 보강 기한을 놓쳐 수업이 사라지는 것을 막음. 기준 일수는 시안 때 제안 |
| **종료 임박 (7일 이내)** | 데이터로 계산 가능(`final_end_date`) | **추가 권장**: 재등록 안내·고정 시간 유지(POL-RN-02) 업무와 연결 |
| **결제 확인 대기·결제 누락** | 없음 | **추가 (A29)**: 4절 설계(`11-accounts-auth-payments.md`) |
| 주의 학생 — 변경권 0개 | 데이터로 계산 가능 | 참고 정보로만(급하지 않음) |
| 주의 학생 — 최근 연속 지각 | 지각을 따로 기록하지 않음 (A04: 지각 시 남은 시간만) | **보류**: 기록 항목을 늘려야 해서 지금은 안 함 |
| **수업 변경 '승인 대기'** | 학생 변경은 규칙 검사 후 **즉시 처리**(POL-CHG-15 확정) → 승인 단계 없음 | **넣지 않음** (정책과 다름). 승인이 필요한 것은 장기 연기·보강 강사 확정뿐 |
| 최근 신청 내역 표 + 탭 | 처리할 일 목록과 많이 겹침 | **넣지 않음**. 대신 학생 상세 화면에 '신청 이력' |

| 통계 메뉴, 날짜 선택, 새로고침 | — | 넣지 않음 (새로고침은 화면 자동 갱신으로 대체) |

## 2. 학생 화면 (아직 없음 — 3·4단계 전에 시안 3개)

| 이미지 요소 | 판단 · 주의 |
|---|---|
| **다음 수업 + [수업 입장] 버튼** | 넣음. 강의실 링크는 `student_my_tutors().meet_url`. 해외 학생은 KST + 현지 시각 함께 |
| **남은 수업 / 남은 변경권 / 수강 종료일(D-day)** | 넣음 (이미지의 3칸 요약). 변경권은 **28일 수강기간 단위**(POL-CHG-03) — 이미지의 "이번 달 변경 사용 1/2"처럼 **달력 월 기준으로 표시하면 안 됨**(A05: 달력상 매월 아님) |
| **빠른 메뉴: 수업 변경 / 보강 신청** | 넣음 (기능 스위치가 켜진 뒤 표시) |
| **신청 진행 상태** (보강 강사 확인 대기·완료 등) | 넣음 — 최근 3건 정도만 |
| 결제·수강 상태, 적립금 잔액 | 넣음 (A29의 4가지, `11-accounts-auth-payments.md` 4절) |
| 알려드려요 띠 (종료 D-n, 6시간 규정) | 넣음 — 문구는 기준표에서 생성(이미지 문구 사용 안 함) |
| 담당 강사 사진·'정규 강사' 배지 | 보류 — 사진 저장·관리 부담. 이름·국가만(지금 함수 범위) |
| 공지사항 목록 | 보류 — 공지 기능이 없음. 필요하면 나중에 |
| 수업 노트·내 수업 기록 메뉴 | 수업 노트 링크(`class_note_url`)만. 기록 화면은 나중 |
| 수업 캘린더, 알림 종, 카카오톡 문의 | 카카오톡 문의 링크만(채널 주소). 캘린더·알림 종은 보류 |
| 사이드 메뉴 9개 | 휴대폰 우선이라 하단 탭 3~4개로 줄이는 안을 시안에 포함 |

## 3. 결론

- 운영자: A안 유지 + **처리할 일 종류 6개 추가 후보**(보강 강사 확인 대기, 보강 강사 미확인, 캘린더 반영 실패, 보강 미신청, 종료 임박, 결제 확인 대기·누락). 모두 지금 DB로 계산할 수 있어 화면 구조를 바꾸지 않고 목록 종류만 늘리면 된다.
- 학생: 이미지의 '다음 수업 + 입장 / 3칸 요약 / 빠른 메뉴 / 신청 상태 / 결제·적립금'을 재료로, 구성이 다른 시안 3개를 학생 화면 개발 전에 보여 드린다.
- 이로써 나중에 화면을 크게 다시 만들 위험은 낮다: 새 요소는 대부분 '목록 종류 추가'이고, 학생 화면은 아직 만들지 않았기 때문.
