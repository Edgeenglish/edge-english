# 정책 충돌 목록 (Conflict Log)

문서끼리 다르거나 규칙이 비어 있는 곳. 수업 횟수·돈·계약에 영향을 주는 것부터 정렬했다.
각 항목은 ① 어떤 문서끼리 ② 실제 문구와 차이 ③ 언제부터 ④ 기존 학생·강사 영향 ⑤ 시스템 구현 문제 ⑥ 추천 해결책 ⑦ 대표 결정 필요 여부 순서.

**판단 원칙** (자세히는 [`process.md`](process.md))
- 최신 문서나 계약서 문구를 자동으로 고르지 않는다.
- 계약(①)은 서명한 사람에게 법적 효력이 있고, 대외 안내(②)는 계약이 아니어도 학생이 믿고 따른 내용이라 함부로 불리하게 적용하기 어렵다. 실제 운영 방식(③)과 날짜를 함께 본다.
- 기존 학생·강사와 신규 등록자에게 다른 조건이 적용될 수 있다. 판본별 적용을 허용하는 구조로 만든다.
- 아래 "추천"은 운영 판단 제안이며 **법률 자문이 아니다.** 계약·환불 관련은 전문가 확인을 권한다.

3. **시점**: 2025-12-24 급여정책부터 $11 기준. TC1은 1년 계약(자동 갱신 조항 없음, 갱신은 서면 동의).

5. **구현 문제**: 시급이 강사마다 다를 수 있음 → 정산 계산이 한 가지 공식이면 틀림.

7. **대표 결정**: 필요 (D-17)

1. **문서**: 수강계약서 SC1·SC2·SC3 ↔ FAQ ↔ 필독안내서 ↔ 강사 가이드 ↔ PDF
2. **문구**: 계약 "수강 기간 종료 후 최대 1주일 이내 재등록" / FAQ(2026-10-12 추가) "수강 종료일 밤 12시(24:00)까지" / 필독안내서(2026-07-09) "수강 기간 종료 당일까지" / 강사 가이드(2026-10-12) "by 11:59 PM (KST) on their course end date" / PDF "종료일 다음 날 23:59"

6. **추천**: 기존 학생에게는 계약대로 **7일**을 적용하는 것이 분쟁 위험이 가장 낮음. 신규 학생을 '당일'로 바꾸고 싶다면 새 계약서(3판)에 명시하고 그 판본부터 적용. 어느 쪽이든 FAQ·안내서·강사 가이드를 같은 문구로 맞춤.
7. **대표 결정**: 필요 (D-1a)

### CF-02 · 이월 기한 ≠ 시간 맡아 두기 기간
1. **문서**: PDF 7장(재등록 대기 기간 미정) — 다른 문서에는 없음
2. **차이**: 1차 보고서에서 둘을 같은 날로 통일하자고 추천했으나, 두 규칙은 성격이 다름.
   - 이월 기한: 학생의 **남은 수업 권리**(계약 사항)
   - 시간 맡아 두기: 강사의 그 요일·시간을 다른 학생에게 배정하지 않고 비워 두는 **운영 규칙**(학생 권리 아님)
3. **시점**: 해당 없음 (새 규칙)
4. **영향**: 둘을 묶으면 이월 기한을 바꿀 때마다 강사 시간 운영도 따라 바뀜. 분리하면 "이월은 7일, 시간은 3일만 맡아 둠"처럼 따로 정할 수 있음.
5. **구현 문제**: 빈 시간 계산과 이월 계산이 서로 다른 값을 써야 함 → 별도 정책 ID로 분리(POL-RN-01, POL-RN-02).
6. **추천**: 별도로 결정. 시간 맡아 두기는 이월 기한보다 길지 않게(맡아 둔 시간이 이월 기한보다 길면 의미 없음). 값이 같아도 되지만 **같은 칸으로 묶지 않음.**
7. **대표 결정**: 필요 (D-1b). 1차 보고서 D-1의 "통일" 추천은 철회.

## 상태값 검토 (14개 유지 여부)

| 질문 | 결론 |
|---|---|
| 14개를 유지할 수 있나 | **예.** 시트·PDF·강사 가이드가 같은 14개를 쓰고 있음 |
| 새 상태가 꼭 필요한 경우 | **D-2에서 A안(재보강 불가)을 고를 때만 1개**: 6시간 전에 보강을 취소했는데 수업이 소진되는 경우(수강권 Y·변경권 N·강사 급여 N). B안이면 추가 없음 |
| 보상 수업 완료는 새 상태가 필요한가 | **아니오.** 상태는 'Normal'/'Make-up completed' 그대로 두고 **수업 종류(보상)**로 구분 → 정산에서 미지급 처리 |
| 변경 신청 상태와 수업 결과 구분 | 결과 14개는 `lessons.class_status`, 신청·보강 진행 단계(신청됨·확정·거절·만료)는 `change_requests`·`makeup_requests`의 상태로 분리 (DB에 반영) |
| 이름 차이 | 강사 가이드의 "Tutor no-show → Make-up needed (within course period)"는 시트의 'Tutor no-show'와 같은 상태. LMS는 시트 이름을 쓰고 가이드 문구를 맞춤 |
