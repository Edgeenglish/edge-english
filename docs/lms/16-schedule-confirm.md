# 16. 신규 배정 확정 관리 (노쇼 대응 1번, 2026-10-21)

근거: 정책 원본 **H22** (2026-10-21 대표 보고 운영사고·개발요구), B01, D-50 4번 절차, A33(채널 승인 범위), POL-OP-19·20.
사고: 강사는 '그 일정 가능'까지만 답했고, 운영자가 학생에게만 최종 확정을 보내고 강사에게는 안 보냄 → 학생만 기다림. 원인은 강사가 아니라 **양쪽 최종 안내 중 한쪽 누락** (강사 귀책·급여 제재로 자동 처리하지 않음).

시안: https://claude.ai/artifact/NGm6bfAKbYrT4U8FoRg2Zc (휴대폰 4장, 파일 사본 `previews/confirm-drafts/`)

## 1. 흐름 (운영자 누르기 횟수)

| 단계 | 운영자 동작 | 시스템 |
|---|---|---|
| ① 등록 마지막 단계 | 강사에게 아직 안 물어봄 → **[저장하고 강사 제안 문구 복사]** (1) → WhatsApp에 붙여 보냄 | 학생·수강권·결제 + 일정안 v1(답 대기) 저장. **수업은 만들지 않음** |
| | 강사가 이미 가능하다고 함 → **[저장 + 확정]** (1) | 아래 ② 확정까지 한 번에 |
| ② 처리할 일 '강사 답 대기' | 강사가 가능 → **[강사 가능 → 확정]** (1) | 한 트랜잭션: 기간 전체 충돌 재검사 → 정규 일정·수업 생성 → **학생·강사 최종 안내 2건(안 보냄)** 생성 → 강사 배정 기록 |
| | 안 됨 → [안 된대요 → 다른 안] → 다른 강사·시간으로 새 버전 제안 | 이전 안은 지우지 않고 '거절'로 남김 |
| ③ 같은 카드가 '양쪽 안내'로 바뀜 | **[강사 문구 복사]** (1), **[학생 문구 복사]** (1) → 각각 붙여 보냄 | 복사한 시각 = 그쪽 '보냄'. **두 줄 모두 '보냄'이 되어야** 매칭 업무가 자동으로 '처리 내역'으로. 한쪽만이면 카드가 빨간 '강사 안내 안 함'으로 남음 |

- 강사에게 먼저 묻는 경우 **4번**(제안 복사·확정·복사 2), 이미 답을 받은 경우 **3번**. 붙여넣기는 메신저 쪽 동작이라 그대로.
- 따로 [보냄]·[완료] 버튼은 없음 (복사 = 보냄, 양쪽 보냄 = 완료). 2026-10-21 '접수 확인 톡'과 같은 방식.
- **복사 = 보냄이지 받음·읽음이 아님** (H22 3번). 화면에도 '보냄 10/21 16:05 (복사한 시각)'으로만 씀.

## 2. 이번에 만든 것 (DB, `supabase/migrations/20261021001000_lms_schedule_confirm.sql`)

- `schedule_plans` 일정안: 등록마다 버전 1, 2, … / 상태 `proposed`(답 대기) · `confirmed` · `declined` · `withdrawn`. 답 대기·확정은 등록당 하나씩만 (DB 제약)
- `schedule_notices` 최종 안내: **확정된 일정안 × 받는 사람(학생·강사) = 1건** (중복 방지 키). 상태 `pending`·`sent`·`failed`·`unknown`, 채널(지금: 학생 카카오톡 수동, 강사 WhatsApp 수동), 보낸 시각·사람·방법(copy/system), 시도 횟수·오류
- 함수(운영자 TOTP만): `admin_propose_schedule`, `admin_confirm_schedule`, `admin_close_plan`, `admin_mark_proposal_sent`, `admin_mark_notice_sent`. `admin_register_student`는 강사·시간을 고르면 일정안으로 저장하고, `tutor_answer = 'accepted'`일 때만 확정까지
- 자동 발송기용(서버만): `lms_notice_result` + `schedule_notice_outbox`(다시 보낼 대상 = pending·failed만, unknown은 운영자 확인)
- 운영자 화면용 `schedule_plan_board`: 답 대기 + 확정했지만 한쪽이라도 안 보낸 것만. 첫 수업까지 남은 시각 제공 (경고 기준 시각은 미결정이라 넣지 않음)
- `admin_tasks` 신규 매칭: **강사 안내 기록(tutor_notified_at) 없이는 DB가 완료를 거부**, 남은 단계에 '강사에게 최종 안내' 추가
- 테스트 (`npm run test:db`, H22 6번 필수 검증): 한 번 확정으로 양쪽 일정·안내 생성 / 강사 답 전엔 수업·안내·배정 없음 / 학생만 보내면 완료 아님 / 실패한 쪽만 재시도·성공은 덮지 않음·불명확은 자동 재시도 안 함 / 확정·제안·복사 두 번 눌러도 한 벌 / 제안 뒤 생긴 휴무와 겹치면 확정 거절 / 학생·비로그인 권한 없음

**아직 안 한 것**
- 화면(①②③)과 문구 생성 — 시안 확정 후
- 시험용 DB 적용 — 화면과 함께 (지금 적용하면 지금 화면의 '등록 저장 · 정규 수업 생성'이 수업 없이 제안만 저장하게 됨)
- **확정 후 일정 변경**(강사·시각·시작일): 새 버전 + 새 안내 2건이 필요하고 예전 안내는 근거가 안 됨(구조는 버전별 키로 준비). 기능은 고정 일정 변경·강사 휴무 처리 때. 지금은 확정된 안이 있으면 새 확정을 거절
- 재등록(B02) 흐름 연결: 같은 안내 표(`schedule_notices`)를 재사용할 예정
